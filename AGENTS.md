## Project

**Neotolis Game Promotion Diary** — self-tracking diary for indie game devs. Log promotion activity (YouTube, Reddit, Telegram, Twitter, Discord, conferences, press); auto-import from registered sources; accumulate stats over time so the user sees, in one chronological feed, which actions moved wishlists and engagement. Hosted SaaS by the author **and** open-source self-host on a small VPS — same image, schema, code.

### Constraints

- **Auth:** Google OAuth only. No email/password.
- **Privacy:** private by default. No public dashboards. All data scoped to `user_id`.
- **Secrets at rest:** envelope-encrypted (KEK from env, per-row DEK), write-once in UI, never logged, never returned in API responses.
- **Transport:** TLS 1.3 + HSTS. Plain HTTP only behind a TLS-terminating proxy.
- **Budget:** indie / zero-budget. Free tier or small VPS. No paid SaaS in the critical path.
- **SaaS == self-host.** Identical behavior. Trusted-proxy headers honored behind bare port / nginx / Caddy / Cloudflare Tunnel.
- **License:** MIT.

## Principles

- **KISS, DRY.** Simple beats clever. A developer landing on the repo for the first time reads a file, follows imports, understands — no tour guide, no "you have to know about X first". If a name doesn't tell you what it does, the name is wrong.
- **Three concrete callers earn an abstraction.** One or two doesn't. Three similar lines beat a premature helper. Feature flags are for soak windows, not "we might swap this later".
- **One source of truth.** Env reads only in `src/lib/server/config/env.ts` (ESLint enforces). Tier classification only in `src/lib/server/services/tier-resolver.ts`. Audit writes only via `src/lib/server/audit.ts writeAudit`. New invariants get a single home — pick it before writing the second copy.
- **Validate at boundaries; trust internal types.** Zod on route input. KEK decryption on key load. Past that, Drizzle types and TypeScript inference are the contract — no defensive re-validation, no fallbacks for impossible cases.
- **Modules don't leak.** A feature module never reaches into another feature module's internals. Cross-cutting concerns (auth, audit, env config, queue, encryption, outbox) live in `src/lib/server/` and get imported by feature modules.
- **Routes call services. Services call the DB.** Hono routes (`src/lib/server/http/routes/`) and SvelteKit `+page.server.ts` files orchestrate; the DB lives behind a service. No `db.select()` in a route handler.
- **SaaS and self-host behave identically.** No code path branches on `APP_MODE`. CI smoke boots the production image with minimal env and refuses to merge if anything depends on a managed service or hard-coded admin allowlist.
- **Forward-only migrations.** Generated by `drizzle-kit generate` from the schema, never hand-written. Run under advisory lock at container boot. `pnpm db:check` catches drift in CI.
- **Atomicity via outbox for dual-writes.** When a DB mutation must trigger a queue job, write the job row in the same transaction using `enqueueViaOutbox(tx, queue, payload)` from `src/lib/server/services/outbox.ts`. Never `boss.send` outside a transaction that just mutated state.
- **Tests land with the feature.** Integration tests hit real Postgres via the service container, never mocks. Feature code without the matching test does not merge.

## Tenant scoping (P0)

Every service function takes `userId: string` as the first non-optional argument. Every Drizzle query against a tenant table filters by `eq(<table>.userId, userId)` in `.where(...)`. ESLint rule `eslint-plugin-tenant-scope/no-unfiltered-tenant-query` catches missing filters at lint time; `tests/integration/tenant-scope.test.ts` catches behavioral drift at CI time.

Cross-tenant access returns **404, never 403** — throw `NotFoundError` from `src/lib/server/services/errors.ts` when the row is missing OR owned by another user. Response body MUST NOT contain "forbidden" or "permission" for tenant-owned resources. `ForbiddenError` is reserved for admin endpoints.

DTO projection (`src/lib/server/dto.ts to<Entity>Dto`) strips ciphertext columns (`secret_ct`, `secret_iv`, `secret_tag`, `wrapped_dek`, `dek_iv`, `dek_tag`, `kek_version`) at the projection boundary. TypeScript erases at runtime; the projection function is the actual barrier. `tests/unit/dto.test.ts` asserts the strip at runtime.

Pino redacts every credential / ciphertext field name (`src/lib/server/logger.ts`): `apiKey`, `accessToken`, `refreshToken`, `idToken`, `secret`, `encrypted_*`, `wrapped_dek`, `dek`, `kek`, `Authorization`, `Cookie`. New secret-shaped field names get a redact path in the same commit.

Anonymous-401 sweep (`tests/integration/anonymous-401.test.ts`) covers every `/api/*` route — every new authenticated route lands in the `MUST_BE_PROTECTED` allowlist. The sweep is the vacuous-pass guard; per-route assertions are the explicit assertions.

## Don'ts

- `db.select().from(<tenant_table>).where(eq(<table>.id, ...))` without `userId` filter.
- `c.json(<row>)` after fetching a row with ciphertext columns — bypass the DTO.
- `process.env` read outside `src/lib/server/config/env.ts` (ESLint `no-restricted-properties` enforces).
- `403 Forbidden` for cross-tenant access on tenant-owned resources — use 404.
- `try/catch` after `db.insert(...)` that "cleans up" a half-write — validate first, INSERT only after pass.
- In-process plaintext-secret cache — defeats envelope encryption.
- Public dashboards, share links, or read-only viewers. No route under `/share`, `/public`, `/embed`. Every page that renders user data is auth-gated.
- Audit log UPDATE / DELETE — INSERT-only. The application DB role MUST NOT have UPDATE / DELETE grants on `audit_log`.
- Error handling, fallbacks, or validation for impossible cases. Trust framework guarantees and internal types. Validate only at system boundaries (route input, external API responses, KEK load).
- "What" comments. Names explain what code does. Comments are reserved for non-obvious "why" — a hidden constraint, a workaround for a known bug, a non-obvious invariant.
- Mocking the database in tests.
- New `boss.send` outside a transaction that just mutated DB state — use the outbox.
- DB queries from route handlers or `+page.server.ts` — go through a service.
- `APP_MODE`-conditioned code paths or features that need Cloudflare-only headers / admin allowlists / managed services without graceful degradation.

## Workflow

PR-only on master; squash-merge auto-deletes the branch. Conventional Commits in PR title (`feat(scope):`, `fix(scope):`, `docs(scope):`, `chore(scope):`). Branch naming: `fix/`, `feat/`, `docs/`, `chore/`. One PR = one logical change. PR body: 1-3 bullet Summary explaining the **why**, Test plan, `Closes #N`. CI gates every PR with `lint-typecheck` + `unit-integration` (Postgres service container) + `smoke` (production Docker image, OAuth dance via `oauth2-mock-server`, cross-tenant + anonymous-401 invariants). Smoke is the load-bearing trust signal — when it's green, a self-host operator can deploy with confidence.

`.planning/` (CONTEXT/RESEARCH/PLAN/SUMMARY/VERIFICATION/STATE/ROADMAP, debug sessions, todos) is local-only (issue #27) — the squash-merge PR body is the canonical phase record on master. `gsd-tools` reads/writes `.planning/` regardless of git tracking.

## Self-review before handoff

Before declaring a PR done, the authoring agent walks Principles + Tenant scoping + Don'ts, cites any drift in the PR body, then runs a second-pass code review (separate agent, fresh context). Also checks CI gate honesty — every new assertion load-bearing, not vacuous-pass — and documentation drift — `AGENTS.md` and `CLAUDE.md` still match the code. New P0/P1 findings get fixed in the same branch. Output goes in the PR body under `## Self-review` and `## Self-review (second pass)`. The human reviewer should not be the first to catch a P0.
