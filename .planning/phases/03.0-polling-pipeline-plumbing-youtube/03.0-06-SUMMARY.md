## Accomplishments

- **Phase 2.1 STUB retired.** The adapter now ships the real implementation per CONTEXT D-06 (service-level YouTube), D-12 (status codes), D-NEW Shorts handling. `grep "implemented in Phase 3"` against `src/lib/server/integrations/youtube-channel-adapter.ts` returns zero matches.
- **Quota math VERIFIED at runtime.** Plan 03.0-01's spike on 2026-05-06 confirmed videos.list = 1 unit per call regardless of id-batch size up to 50. This adapter takes that contract literally — `pollStats` chunks at 50 and issues one HTTP call per chunk; the `if (videoIds.length > 50) throw` guard is a defense-in-depth against future regression.
- **Privacy floor preserved.** No `process.env` access outside config/env.ts (grep returns 0); no plaintext-secret cache (AP-3 — operator's API key read from env at call time and passed to fetch as the URL `key=` param, never stored on a module-level variable across calls).
- **Per-tenant fairness gate active.** Every HTTP call carries `quotaUser=hash(events[i].userId)` (16 hex chars from SHA-256). When a single tenant aggressively polls, Google's per-end-user fairness gate caps that tenant's slice of the operator's daily quota; other tenants keep working.
- **Shorts detection landed at the adapter layer.** `contentDetails.duration` is parsed via ISO-8601 regex (`PT(\d+H)?(\d+M)?(\d+S)?`); the snapshot's `metadata.duration_seconds` + `metadata.is_short` are populated on every `ok` status. Test 10b pins the inclusive ≤60s boundary explicitly.
- **Wave 1 unblocked for Plan 03.0-09 worker handlers.** Plan 09's `poll-active.ts` job handler will call `youtubeChannelAdapter.pollStats(events, null)` and `writeSnapshot` per result — both modules now exist with stable signatures.

## Public API of the adapter

```typescript
export const youtubeChannelAdapter: DataSourceAdapter = {
  kind: 'youtube_channel',

  // 1 quota unit per call. Filters response items to publishedAt > since.
  // Returns [] gracefully when source.metadata.uploadsPlaylistId is missing
  // (Plan 03.0-10 channel-context trigger backfills it on first paste).
  pollContent(source: PollableSource, since: Date): Promise<RawEvent[]>;

  // 1 quota unit per ≤50 ids per call. Returns StatsSnapshot[] aligned to
  // input order. Groups by userId so quotaUser is correct per call.
  pollStats(
    events: PollableEvent[],
    source: { id: string; userId: string } | null,
  ): Promise<StatsSnapshot[]>;
};
```

## Error Mapping Table

| HTTP outcome | response.errors[].reason | SnapshotStatus |
| ------------ | ------------------------ | -------------- |
| 200 + item present in `response.items` | n/a | `ok` (with `metrics` + `metadata`) |
| 200 + item missing from `response.items` | n/a | `not_found` (private/deleted/embedded-disabled) |
| 403 | `quotaExceeded` | `rate_limited` (worker defers; scheduler pauses) |
| 403 | other / missing | `auth_error` (event tier flips to Unavailable) |
| 404 | n/a | `not_found` |
| Other 4xx/5xx | n/a | `auth_error` (placeholder; caller logs + retries) |
| Empty `SERVICE_YOUTUBE_API_KEYS` env | n/a | `auth_error` (degrade-to-no-op for self-host parity) |

## Decisions Made

(See frontmatter `key-decisions` block for the canonical list — repeated here narratively.)

- **Inlined `pickKeyForJob` + `hashApiKeyId` rather than imported from `services/youtube-quota-tracker.ts`.** Plan 03.0-03 (the canonical home of these helpers) was running in parallel in the same Wave 1 when this plan started executing. Importing from a sibling-agent's not-yet-committed file would have produced a non-deterministic build outcome — when the typecheck ran, the file might or might not exist depending on which agent committed first. The inlined block ships a minimal contract: round-robin across `env.SERVICE_YOUTUBE_API_KEYS` (no quota gating, since the gate logic belongs in 03.0-03), and SHA-256 16-hex-char hashing for the `quotaUser` parameter. A doc-comment in the adapter explains the swap is a one-line follow-up commit. **Plan 03.0-03 actually landed in commit `835ed04` between this plan's RED and GREEN phases**, which means the swap is now safe to do — but it is out of scope for this plan and is tracked as a follow-up below.

- **DataSourceAdapter interface evolution accepted as breaking.** The Phase 2.1 STUB had `pollStats(event, source) → StatsSnapshot` (single event); Plan 03.0-06 evolves it to `pollStats(events[], source) → StatsSnapshot[]` (batch) so the 50× quota saving on `videos.list` actually flows through to consumers. `RawEvent.kind` and `RawEvent.metadata` were also made optional, and `StatsSnapshot.metrics` was made optional (absent on error statuses). Verified safe: `grep DataSourceAdapter|RawEvent|StatsSnapshot` against the codebase showed the only consumers were the test file and the adapter itself. Plan 03.0-09 worker handlers (not yet written) consume the new batch signature explicitly per their plan's `<read_first>` cite.

- **Dynamic-import + `vi.resetModules()` test pattern.** `env.ts` parses `process.env` once at module load (PITFALL P2 mitigation #4 also scrubs `APP_KEK_BASE64` after parse), and the adapter caches `env.YOUTUBE_API_BASE_URL` + `env.SERVICE_YOUTUBE_API_KEYS` at its own module load. Without `vi.resetModules()` between suites, the adapter would carry stale env values from whichever test file vitest loaded first in the worker process. The `loadAdapter()` helper does `vi.resetModules()` + re-seeds `APP_KEK_BASE64` + dynamic-imports the adapter module fresh. Mirrors the pattern in `tests/unit/youtube-quota-tracker.test.ts`.

- **Shorts boundary at ≤ 60s (inclusive).** UI-SPEC says "Shorts" badge fires for videos ≤ 60s. PT1M (60s) → `is_short=true`; PT1M1S (61s) → `is_short=false`. Test 10b pins the boundary explicitly.

- **AbortController test asserts signal propagation, not actual fire.** `expect(calls[0]!.signal).toBeInstanceOf(AbortSignal)`. Unit tests must complete in <5s; spinning a real 30s timer is a CI cost we explicitly avoid. The `30_000` value is verified via grep against the source.

**2. [Rule 1 — Bug] `noUncheckedIndexedAccess` strict-mode array access**

- **Found during:** Task 1 (between RED and GREEN — typecheck after the GREEN-phase implementation landed).
- **Issue:** `tsconfig.json` has `noUncheckedIndexedAccess: true`. Direct `array[idx]` access returns `T | undefined`; the test file and the adapter's `pollStatsBatch` had 30+ such accesses that failed type-check. None of the accesses were actually unsafe (they were all bounded by `for` loops or `chunk.length`), but TypeScript can't prove that without explicit non-null assertions.
- **Fix:** Added `!` non-null assertions at every bounded array access. Examples: `keys[idx]!` (bounded by `idx % keys.length`); `chunk[j]!` and `snapshots[j]!` (both bounded by `for (let j = 0; j < chunk.length; j++)` after we ensure `snapshots.length === chunk.length` from `pollStatsBatch`); `calls[0]!.url` (after `expect(calls).toHaveLength(1)`); `snap!.status` (after destructuring `const [snap] = ...`).
- **Files modified:** `src/lib/server/integrations/youtube-channel-adapter.ts` (2 occurrences); `tests/unit/youtube-channel-adapter.test.ts` (~30 occurrences).
- **Verification:** `pnpm typecheck` 0 errors after the fix; previously 35.
- **Committed in:** `9cbec3f` (bundled with GREEN phase since the assertions are part of the same commit's typecheck-clean implementation).
