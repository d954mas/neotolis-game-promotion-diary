## Accomplishments

- **POST /api/events/:id/refresh-poll** (extension to `src/lib/server/http/routes/events.ts`) — calls `requestRefreshPoll(c.var.userId, c.req.param('id'), c.var.clientIp, c.req.header('user-agent'))`. Returns `{enqueued: true, queue: 'poll.user', eventId}` on 200. Error mapping via `mapErr`: NotFoundError → 404 `{error: 'not_found'}`; AppError flows through with status+code+metadata. The route handler explicitly sets `Retry-After: <seconds>` header from `err.metadata.retryAfterSeconds` on `too_many_refreshes` errors before deferring to `mapErr` for the JSON body — UI-SPEC interaction contract: Plan 03.0-11's RefreshNowButton reads the header to drive the cooldown countdown without round-tripping the metadata payload.
- **DELETE /api/me/account/purge** (extension to `src/lib/server/http/routes/account.ts`) — calls `purgeAccount(c.var.userId, {ignoreRetention: true, ipAddress: c.var.clientIp})`. Returns `{purged: true, rowCounts: {...}}` on 200. The cascade DELETE in the same tx removes session rows so any subsequent request with the pre-purge cookie returns 401 (intended logout); Plan 03.0-12's SvelteKit client reads the 200 and redirects to /login per UI-SPEC interaction contract.
- **Account-state middleware allowlist extension** — added `DELETE /api/me/account/purge` to `ALLOWED_WHEN_DELETED` in `src/lib/server/http/middleware/account-state.ts`. The CTA's primary audience IS the soft-deleted user pressing the button on AccountDeletedBanner; without the exemption the route would 423 Locked for the exact users it targets.
- **Anonymous-401 sweep activations** — `MUST_BE_PROTECTED` allowlist in `tests/integration/anonymous-401.test.ts` extended with `/api/events/:id/refresh-poll` + `/api/me/account/purge` (the structural vacuous-pass guard). ## Decisions Made

See `key-decisions` in frontmatter. Highlights:

- **Account-state allowlist gains DELETE /api/me/account/purge** — the only way the soft-deleted user can press the Permanent-delete-now CTA is if the middleware lets the request through. The cascade DELETE in the same tx invalidates the session anyway, so account-state's gate becomes irrelevant on the next request.
- **Retry-After header set in the route handler, not in mapErr** — mapErr is the JSON body translator; it shouldn't grow a header policy. The 429 → Retry-After contract is route-specific; future routes with header-bearing AppError responses follow the same split.
- **purgeAccount called with c.var.clientIp (real IP), not 'system'** — the CTA path has request context. Phase 02.2 D-15's 'real IPs from day one' invariant honored. Cron path (Plan 09) defaults to 'system' since it has no request context.
- **Both vacuous-pass sweep AND explicit per-route 401 assertions** — AGENTS.md §3 requires both layers. The sweep catches "route disappeared from allowlist"; the per-route assertions catch "route's auth gate stops firing". Two directions, two tests.
