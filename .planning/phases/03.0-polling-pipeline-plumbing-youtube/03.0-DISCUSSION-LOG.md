## Clarifying Questions Answered Plainly (no AskUserQuestion)

- **YouTube quota cost & billing:** 10k unit/day free per Cloud project; $0.50/1000 unit above (only if operator explicitly enables billing — default = hard cap, no surprise charges).
- **Service vs per-user model trade-off:** Per-user adds Cloud Console friction for typical indie devs; service-level pools quota efficiency by sharing snapshots across tenants by `video_id`.
- **Two users on same channel = one or two requests?** Originally per-user model = 2 requests; service-level model (D-06) = 1 request.
- **Multiple SERVICE_YOUTUBE_API_KEYS:** Technically yes, round-robin; Google ToS allows ~2-3 keys per Cloud account before flagging quota circumvention; paid tier ($0.50/1000 unit) is safer scale path.
- **YouTube Shorts vs regular videos:** Same endpoints, same quota cost, distinguished only by `contentDetails.duration` ≤60s in response. No special handling needed; metadata.is_short stored at snapshot time for Phase 4 UX.
- **`videos.list` 50 = max batch:** 50 is max ID-list per single call (1 unit). "50 latest" requires `playlistItems.list` separately. Auto-import incremental polling = ~1 unit per source per cycle (filter publishedAt > last_polled_at).
- **Channel auto-source on paste?** No — manual paste does NOT auto-create data_source row (D-11). Source rows are user-explicit via /sources/new.
- **6 distinct polling operations and their costs** explained in chart form during Q-E follow-up.
