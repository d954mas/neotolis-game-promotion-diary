## Decisions Made

See `key-decisions` in frontmatter. Highlights:

- **Lazy-import youtube-quota-tracker from snapshot-writer** to defuse the parallel-agent coordination problem on the same branch. The plan's `<key_links>` static-import contract is preserved at the call-site (`incrementUsage` is invoked with `tx`); a dynamic import resolves the same symbol Vitest's `vi.mock` would intercept anyway. The runtime cost is one promise resolution at first invocation; the alternative (static import) would have produced a missing-module error in my agent's verification window before Plan 03's commit landed on the same branch.
- **Constraint-name-keyed 23505 translation** rather than guessing-by-input-shape. Multiple partial unique indexes can fire from one events INSERT (auto-import dedup vs manual-paste dedup post Plan 01); routing by `constraint` field of the pg error is the only reliable discriminator. The new helper `pgUniqueViolationConstraint` handles both `constraint` and `constraint_name` driver shapes.
- **Pre-existing 409 status preserved for events_user_kind_source_ext_unq** — auto-import path catches and silently skips, so the user-facing surface never sees that status. Changing it to 422 would have rippled into back-compat callers (any client that discriminates by status) for no user-facing benefit.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Lazy-import youtube-quota-tracker to unblock parallel-agent verification**

- **Found during:** Task 1 verification (`pnpm vitest run --project=unit youtube-snapshot-writer.test.ts`).
- **Issue:** The plan specifies `import { incrementUsage } from "./youtube-quota-tracker.js"` at the top of `youtube-snapshot-writer.ts`. The parallel Plan 03 agent had not yet committed `youtube-quota-tracker.ts` when my agent ran tests — the static import resolved to "Cannot find module './youtube-quota-tracker.js'" and 0 tests ran.
- **Fix:** Wrapped the call inside a local async helper that does `await import("./youtube-quota-tracker.js")`. The plan's `<key_links>` semantic ("calls incrementUsage in same db.transaction") is preserved (the call still runs INSIDE the same `db.transaction` callback, with `tx` passed explicitly); the lazy-resolution defers the module-binding moment from agent boot to first `writeSnapshot` invocation. Vitest's `vi.mock(...)` of `./youtube-quota-tracker.js` honors both static and dynamic imports equally.
- **Files modified:** `src/lib/server/services/youtube-snapshot-writer.ts`
- **Verification:** 8/8 unit tests pass; the structural assertion that `incrementUsage` receives `tx !== undefined` confirms the contract.
- **Committed in:** `c279d58` (Task 1 commit).

**2. [Rule 3 — Blocking] queue-client.getBoss helper missing**

- **Found during:** Task 2 (refresh-poll.ts authoring).
- **Issue:** Plan's example imports `getBoss` from `queue-client.ts`, but Phase 1 only exported `createBoss` / `stopBoss`. Worker + scheduler entrypoints own their own boss instance with their own SIGTERM lifecycle; the APP role had no equivalent — each HTTP handler booting its own boss would burn one Postgres connection per request and have no graceful-stop owner.
- **Fix:** Added `getBoss` (memoized boss singleton) + `resetBossSingletonForTesting` to `queue-client.ts`. The first call boots a boss via the existing `createBoss`; subsequent calls resolve from the memoized promise. Lifecycle is process-lifetime (Node's process exit drains pg-boss's own pool); a future plan can wire the SIGTERM unwind path if needed.
- **Files modified:** `src/lib/server/queue-client.ts`
- **Verification:** Lint + typecheck clean; integration tests mock `getBoss` so they don't depend on a live boss.
- **Committed in:** `9e49ad9` (Task 2 commit).

**3. [Rule 1 — Bug] Test serialization tripped on Drizzle column circular refs**

- **Found during:** Task 1 first verification run.
- **Issue:** The snapshot-writer unit test serialized the WHERE clause to assert tenant-scope (userId in the clause). My initial `JSON.stringify` of the Drizzle SQL chunk threw `TypeError: Converting circular structure to JSON` because Drizzle column instances back-reference their parent table.
- **Fix:** Replaced JSON.stringify with `collectColumnNames` — a WeakSet-tracked walker that gathers `name` strings (snake_case column identifiers like "user_id" / "id") from the clause graph. The structural assertion then checks that the collected list contains "user_id" (tenant-scope guarantee).
- **Files modified:** `tests/unit/youtube-snapshot-writer.test.ts`
- **Verification:** 8/8 unit tests pass; the tenant-scope test fails loudly if the WHERE clause loses its userId column reference (regression guard).
- **Committed in:** `c279d58` (Task 1 commit; bundled because it's intrinsic to the unit-test approach).

**4. [Rule 2 — Missing Critical] events.ts pgUniqueViolationConstraint helper**

- **Found during:** Task 3 (events.ts D-15 translation).
- **Issue:** Plan's example shows `e.constraint ?? e.constraint_name` inline in the catch block. The pg error shape varies: `node-pg` exposes `constraint`, older drivers (and some pg-mem mocks in tests) use `constraint_name`. Inlining the access in the catch block worked but duplicated the conditional everywhere and lacked a clear name for the discriminator concern.
- **Fix:** Extracted to `pgUniqueViolationConstraint(e: unknown): string | null` next to the existing `isPgUniqueViolation` helper. The catch block now calls one named function and switches on the returned string. Future plans (Phase 3.1 reddit dedup, Phase 4 auto-import per-platform constraints) plug into the same helper without re-implementing the type-guard.
- **Files modified:** `src/lib/server/services/events.ts`
- **Verification:** Typecheck + lint clean; the test `events-manual-paste-dedup.test.ts` exercises the path.
- **Committed in:** `e3933eb` (Task 3 commit).
