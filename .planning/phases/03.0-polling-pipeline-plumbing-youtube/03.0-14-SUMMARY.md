## Accomplishments

- **`tests/smoke/lib/youtube-mock.mjs` deterministic 50-video fixture.** Node 22 stdlib `node:http` stub (no install). Three endpoints implemented, each returning the exact response shape the worker's zod parsers expect:
  - `GET .../videos` → 50 items with deterministic view/like/comment counts (every 5th item carries `duration: PT45S` so the worker's Shorts detector exercises both branches; the rest are `PT4M13S` long-form).
  - `GET .../playlistItems` → 10 items with `resourceId.videoId` referencing `mock-video-{0..9}` so a worker that does the canonical playlistItems-then-videos chain finds matching IDs.
  - `GET .../channels` → 1 channel with `contentDetails.relatedPlaylists.uploads = UUmockchannel0123456789ab` so the channel-context-backfill handler can resolve the uploads playlist.
  - Pathname suffix matching supports both `http://localhost:$port/videos` (relative base) and `http://localhost:$port/youtube/v3/videos` (full base) — accommodates either form of YOUTUBE_API_BASE_URL.
  - Anything else returns 404 in Google's error shape so a future endpoint added without extending the stub fails LOUDLY in the worker's response parser instead of silently mismatching.
- **`tests/smoke/lib/youtube-mock.sh` lifecycle wrapper.** `start_youtube_mock` allocates a free port via `node -e 'createServer().listen(0)...'` (cross-platform, works on the GitHub Actions Linux runner and macOS), spawns the .mjs in the background, polls `/videos` for up to 5s as a ready-check (the stub mirrors Google — no /healthz endpoint), and exports `YOUTUBE_MOCK_PORT` + `YOUTUBE_MOCK_PID` for the parent shell. `stop_youtube_mock` SIGTERMs first, gives 2s to drain, then SIGKILLs as a safety net. EXIT trap auto-cleans the mock so a half-failed assertion doesn't leak a zombie Node process.
- **`tests/smoke/lib/phase30-flow.sh` 6-step assertion chain.**
  1. Source + start youtube-mock; export `YOUTUBE_API_BASE_URL=http://localhost:$YOUTUBE_MOCK_PORT`.
  2. Re-launch smoke-worker + smoke-scheduler with the Phase 3.0 env (`SERVICE_YOUTUBE_API_KEYS=mock-key`, empty `ADMIN_EMAIL_ALLOWLIST`, mock URL); wait for `worker ready` / `scheduler ready` ready signals.
  3. Query pgboss.schedule via `docker exec smoke-app node -e '...'` and assert ALL FOUR Phase 3.0 cron names registered (`scheduler.tick.active`, `scheduler.tick.cold`, `youtube.quota_reset`, `purge.daily` — Plan 09 Pattern A names).
  4. Create a `kind=youtube_video` event via POST /api/events with a `https://www.youtube.com/watch?v=mock-video-0` URL (the createEvent service auto-derives `external_id="mock-video-0"` per Plan 02.1-17 enrichment); call POST /api/events/:id/refresh-poll which enqueues to `poll.user`; wait up to 60s for `youtube_video_snapshots` row + assert `events.last_polled_at IS NOT NULL` AND `events.last_poll_status = 'ok'`.
  5. With empty allowlist, assert `curl /api/admin/quota` returns 404 AND `curl /admin/quota` HTML returns 404 (D-16 self-host parity gate by construction; two assertions because the SvelteKit page loader fetches the API and a regression on either side could mask the other).
  6. SIGTERM smoke-worker; assert it exits within 65s (Phase 1 D-22 60s graceful drain + 5s docker overhead). Re-asserts the inherited drain holds with the new poll.* subscriptions in place.
- **`tests/smoke/self-host.sh` extension.** Sources phase30-flow.sh after the Phase 2.1 unified-flow assertions; final summary log line updated to "Phase 1 + Phase 2 + Phase 2.1 + Phase 3.0 scope". Comment block lists the 6 assertions inline so an operator skimming the harness sees what Phase 3.0 covers without opening the helper.
- **`.github/workflows/ci.yml` env propagation.** Smoke job's `env:` block gains `SERVICE_YOUTUBE_API_KEYS: mock-key` and `ADMIN_EMAIL_ALLOWLIST: ''`. `YOUTUBE_API_BASE_URL` is set dynamically by the script after `start_youtube_mock` allocates a free port (cannot be a static env value); the comment block in ci.yml documents this for operator readability.
- **`eslint.config.js` test carve-out extended.** `tests/**/*.mjs` added to the `no-restricted-properties` ignore set so the new `youtube-mock.mjs` fixture (which reads `process.env.YOUTUBE_MOCK_PORT`) passes lint. Rule 3 deviation — required to unblock Plan 14 lint pass.
