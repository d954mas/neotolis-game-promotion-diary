# Phase 03.0 Plan 07: Admin Middleware + /api/admin/quota Route Summary

**Env-allowlist gate (`adminAllowlist`) responds 404 (not 403) for non-allowlisted callers; empty allowlist preserves self-host parity by construction; `GET /api/admin/quota` aggregates today's per-key YouTube quota usage rows + last 50 service-level audit entries (cross-tenant; operator signal pane); auth gate fires before allowlist gate so anonymous → 401 and non-allowlisted authenticated → 404; sweep + cross-allowlist probes activated.**

## Accomplishments

- **`adminAllowlist` middleware (Pattern 5).** Reads `env.ADMIN_EMAIL_ALLOWLIST` (zod-transformed Set<string>, lowercased + trimmed at boot per Plan 03.0-01). Caller email is also lowercased on every request for case-insensitive match. Empty Set ⇒ membership check fails for every authenticated user ⇒ all `/api/admin/*` returns 404 (self-host parity by construction; no `APP_MODE` branching). Defensive fallback when `c.var.userEmail` is undefined: treated as non-allowlisted (404).
- **`tenantScope` extension — c.var.userEmail.** The existing Phase 1 tenantScope read `result.user.id` + `result.session.id` from Better Auth's `getSession`; we now also read `result.user.email` and stash it on `c.var.userEmail`. Better Auth already returns email on the session result projection — zero added DB cost.
- **`GET /api/admin/quota` route (RouteVars-typed Hono sub-router).** Mounted under `/api/admin` after `tenantScope` (global `/api/*`) and `adminAllowlist` (`/api/admin/*`). Response: `{today, keys: QuotaKeyRow[], audit: ServiceAuditEntry[]}`. Empty arrays when no usage / no audit rows today; `today` always present as `'YYYY-MM-DD'` in America/Los_Angeles (via `todayPacific()` from Plan 03's `youtube-quota-tracker`).
- **`loadAdminQuotaPage()` service layer.** Pure data layer (no Hono, no auth concerns). SELECTs `youtube_service_quota_usage` rows where `date_pacific = todayPacific()` (the public-data table is already in ESLint's TENANT_TABLES allowlist per Plan 03.0-01). SELECTs last 50 `audit_log` rows where `action IN (quota.service_throttled, purge.completed, auto_import.deferred, poll.failed)` ORDER BY `created_at DESC` — this is intentionally cross-tenant per CONTEXT D-16 / DV-3 / Open Question 4. The cross-tenant query carries an inline `eslint-disable-next-line tenant-scope/no-unfiltered-tenant-query -- <justification>` per AGENTS.md Pitfall 7.
- **`toQuotaKeyRow` projection.** Computes `pctOfDaily = round(estimatedUnits / 10_000 * 1000) / 10` (1 decimal) + `status: 'ok' | '80_throttle' | '95_throttle'` using the imported `THROTTLE_*_THRESHOLD` constants from Plan 03's `youtube-quota-tracker.ts`. The thresholds (8000 / 9500) exist in only one place — extending Pitfall 7 / Plan 03 single-source-of-truth discipline.
- **`toServiceAuditEntry` projection.** Mirrors `toAuditEntryDto` shape but intentionally omits `userId` even though the lookup is cross-tenant — the operator UI shows verb + metadata + time only, not "which tenant triggered this".
- **Sweep activations.** `tests/integration/anonymous-401.test.ts` MUST_BE_PROTECTED list now includes `/api/admin/quota` (the prior `// uncomment after Plan 03.0-07` comment is replaced with a live entry); the it.skip stub for the anonymous-401 contract is now a live assertion. `tests/integration/tenant-scope.test.ts` cross-allowlist probe is now a live assertion: a non-allowlisted authenticated user receives 404, and the response body excludes "forbidden" / "permission" per AGENTS.md AP-4.
- **AGENTS.md compliance asserted:** AP-4 wire-format check at three layers (unit harness onError-style, integration empty-allowlist branch, integration non-allowlisted-user branch). Each asserts `body !match /forbidden|permission/i`.

## Decisions Made

- **Direct `c.json 404` from middleware (NOT `throw NotFoundError`).** The plan's RESEARCH-md Pattern 5 snippet calls for `throw new NotFoundError()`, which would propagate as an uncaught exception because the existing app has no global Hono `onError` handler. Two paths existed: (a) install a global onError that maps `NotFoundError → 404`, or (b) match the `tenantScope` 401 + `accountState` 423 precedent and respond directly. Chose (b) — minimal blast radius (only this middleware changes shape), matches existing convention, identical wire format to `mapErr`'s NotFoundError emission so callers cannot distinguish.
- **Extend `tenantScope` to set `c.var.userEmail`.** The existing tenantScope reads from Better Auth's getSession which already returns `result.user.email`; surfacing that value adds zero cost. Alternative (look up email separately in the admin middleware) would have added a DB round-trip per `/admin/*` request and a circular dependency from the middleware on the user table.
- **Re-export DTO projections via `dto.ts` barrel.** The projections themselves live in `admin-quota-read.ts` because their derivation (pctOfDaily / status) reads `THROTTLE_*_THRESHOLD` from `youtube-quota-tracker`; centralizing the math there avoids a circular import and keeps the threshold literals in one place. The `dto.ts` barrel re-export gives callers a single import path consistent with the rest of Phase 2/3 DTO discipline.
- **Cross-tenant audit aggregation with inline eslint-disable.** AGENTS.md mandates a `--` justification on every tenant-scope override; the inline comment explicitly cites CONTEXT D-16 / DV-3 / Open Question 4 in 03.0-RESEARCH.md. The security property is the allowlist gate; non-allowlisted users return 404 before the loader runs, so the cross-tenant SELECT is safe by construction.
- **Mount admin allowlist AFTER the global `tenantScope` + `accountState` (soft-delete guard).** A soft-deleted admin user would hit `accountState`'s 423 Locked before reaching the allowlist gate; this is intentional — a soft-deleted operator cannot view `/admin/quota` until they restore their account. Out-of-scope edge case for this plan; revisit if Phase 6+ needs an operator escape hatch.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Direct `c.json 404` from middleware instead of `throw NotFoundError`**
- **Found during:** Task 3 (mounting the middleware in app.ts)
- **Issue:** The plan's `<action>` specified `throw new NotFoundError()` from the middleware. Hono's default error path on uncaught middleware exceptions returns 500 unless a global `onError` handler is installed. The existing app has no global `onError` (per-route handlers call `mapErr` from try/catch blocks; that pattern doesn't reach middleware-thrown errors). Wiring a `throw` would have produced 500 → integration test failure on the empty-allowlist branch.
- **Fix:** Replaced `throw new NotFoundError()` with `return c.json({error:'not_found'}, 404)` directly from the middleware. Wire format identical to what `mapErr` emits for `NotFoundError`. Matches the existing `tenantScope` 401 + `accountState` 423 patterns. Updated the unit test to drop the synthetic `app.onError` mapping that was paired with the throw.
- **Files modified:** `src/lib/server/http/middleware/admin.ts`, `tests/unit/admin-middleware.test.ts`
- **Verification:** 7/7 unit tests pass; integration tests load into the suite (deferred to CI's Postgres service container — local Postgres unavailable, see Issues Encountered).
- **Committed in:** `e04d889`

**2. [Rule 2 - Missing Critical] `tenantScope` did not set `c.var.userEmail`**
- **Found during:** Task 1 (writing the unit test for the middleware)
- **Issue:** The plan assumed `c.var.userEmail` was already populated by Phase 2 better-auth integration. Inspection of `src/lib/server/http/middleware/tenant.ts` showed it set only `userId` + `sessionId`. Without the email, the admin gate would crash on `c.var.userEmail.toLowerCase()` (TypeError on undefined).
- **Fix:** Extended `tenantScope` to read `result.user.email` from Better Auth's session result and call `c.set("userEmail", result.user.email)`. The session result already carried email (no extra DB cost). Updated the `MiddlewareHandler` Variables generic to include the new field. Defensive fallback in admin middleware: `(c.var.userEmail ?? "").toLowerCase()` so a missing value doesn't crash, just fails the membership test (404).
- **Files modified:** `src/lib/server/http/middleware/tenant.ts`
- **Verification:** 7/7 unit tests including the "missing userEmail (defensive)" case pass; downstream consumers of tenantScope continue to compile (RouteVars unaffected — the new field is purely additive).
- **Committed in:** `a4cd9b1`
