# Phase 3.0 — UI Design Contract

> Visual and interaction contract for the polling-pipeline-plumbing + YouTube phase. Generated by gsd-ui-researcher; consumed by gsd-ui-checker, gsd-planner, gsd-executor, gsd-ui-auditor.
>
> **Scope.** Phase 3.0 introduces FOUR frontend touchpoints on top of the Phase 2.1 / 02.2 design baseline:
>
> 1. `<PollingBadge>` live state — replaces the Phase 2.1 placeholder with 4 user-facing variants (Hot · Cold · Frozen · Unavailable) plus a refresh-now icon affordance with 5 min cooldown.
> 2. `/admin/quota` page — env-allowlist-gated operator surface showing today's `youtube_service_quota_usage` per key + last 50 service-level audit entries.
> 3. `<AccountDeletedBanner>` Permanent-delete-now CTA — activated (the Phase 02.2-04 hidden CTA per DV-6) and wired to `DELETE /api/me/account/purge` via the Type-DELETE `<ConfirmDialog>` (D-S3 pattern reused).
> 4. `/sources/new` channel-registration backfill picker — a second-step UI with 5 presets (1 / 7 / 30 / 90 days / Everything; default 30) shown when the chosen kind is `youtube_channel` and `auto_import` is ON.
>
> **Stack reality (UNCHANGED from Phase 2 + 2.1 + 02.2).** SvelteKit 2.58 + Svelte 5 (runes) + Paraglide JS 2 + native CSS using design tokens in `src/app.css`. No Tailwind, no shadcn, no React, no component library. Indie-budget constraint (PROJECT.md) and locked-stack constraint (RESEARCH.md §"Standard Stack") forbid adding any new top-level UI dependency in Phase 3.0. Lucide-style icons remain inline-SVG geometric forms (`KindIcon` / `SourceKindIcon` precedent).
>
> **Inheritance.** This spec INHERITS the entire Phase 2 + 2.1 + 02.2 design contract verbatim — spacing scale, typography, color tokens, Layout & Responsive Contract (incl. 360px hard floor), Form interaction contract, Accessibility floor (44px touch target on icon-only buttons; `:focus-visible` 2px accent outline; `role="status"`/`role="alert"` for live regions), ConfirmDialog speedbump + Type-DELETE pattern, theme model (`data-theme=light/dark/system`). The sections below specify ONLY what 3.0 changes or adds.
>
> **Aesthetic stance (unchanged).** Tool-feel, terminal-leaning, dense information OK, calm > flashy, privacy-only with zero growth surfaces. Quota numbers render plain (no charts, no progress-bar Christmas tree); the operator gets honesty, not ambiance.
>
> **English-only UI per UX-04** (AGENTS.md). All copy below is the literal English string that lands in `messages/en.json`; Russian discussion in 03.0-CONTEXT.md is internal-only and does NOT translate to user-facing strings.

## Color

**UNCHANGED tokens, four new usage rules.** The 60/30/10 split, all CSS custom properties, and dark/light/system theme handling stay identical to Phase 2 + 2.1 + 02.2 (`src/app.css` not edited). New components consume the existing tokens.

### PollingBadge variant color rules (live state)

The component renders WITH NO color fill — variant differentiation is by inline icon color and text color only, on a transparent background bordered with `--color-border` (matches the existing dashed-border placeholder visual). This keeps a 50-row /feed quiet (the "no Christmas tree" rule from Phase 2.1).

| Variant | Icon stroke color | Text color | Border |
|---------|-------------------|------------|--------|
| `Hot · checked Xh ago` | `var(--color-success)` (green) | `var(--color-text)` | `1px solid var(--color-border)`, NOT dashed |
| `Cold · yesterday` / `Cold · Xd ago` | `var(--color-info)` (cyan) | `var(--color-text-muted)` | `1px solid var(--color-border)`, NOT dashed |
| `Frozen · refresh to update` | `var(--color-text-muted)` (neutral) | `var(--color-text-muted)` | `1px dashed var(--color-border)` (dashed signals inactive — same affordance as the Phase 2.1 placeholder) |
| `Unavailable · last seen Xd ago` | `var(--color-destructive)` (red) | `var(--color-text-muted)` | `1px solid var(--color-border)`, NOT dashed |

**Why the restraint:**
- We DO NOT fill PollingBadge with `--color-success` for the Hot variant. A green-filled pill on every card on a busy feed is loud and competes with the Mine border-left + overlay-Mine pill. Color is in the tiny icon, not in the chrome.
- `Frozen` uses dashed border deliberately — it signals "the system has stopped polling on its own; the only way to update is the refresh icon", which mirrors the Phase 2.1 placeholder's "this is going to do something later" affordance.
- `Unavailable` uses red icon + muted text, NOT a destructive-filled pill. This is a status, not an action; the destructive fill is reserved for explicit destructive-action buttons (Permanent-delete-now CTA, ConfirmDialog confirm).

### QuotaKeyTable status pill color rules

The pill is the only place in `/admin/quota` that uses fills. Each row corresponds to one operator API key.

| Status | Pill background | Pill text |
|--------|-----------------|-----------|
| `OK` (< 80% of 10 000 daily) | `var(--color-success)` at 12% alpha (subtle green wash) | `var(--color-success)` |
| `80% throttle — Cold paused` | `var(--color-info)` at 12% alpha (subtle cyan wash) | `var(--color-info)` |
| `95% throttle — Active paused` | `var(--color-destructive)` at 12% alpha (subtle red wash) | `var(--color-destructive)` |

Alpha values are CSS `color-mix(in srgb, var(--color-X) 12%, transparent)` — Phase 2 already established this idiom for `<RetentionBadge>` warning state. No new tokens needed.

### Accent (10%) — new surfaces

| Surface | Why |
|---------|-----|
| `<BackfillPicker>` selected radio circle outline | The selected preset is a primary form decision; the outline matches the form's `Save source` CTA visually so the user reads "this is locked in" |
| `<AdminLayout>` admin-mode breadcrumb left-border (3px) | Single accent stripe on the left edge of the breadcrumb so admin mode is unambiguous without filling a banner |

### Destructive — new surfaces

| Surface | Why |
|---------|-----|
| `<AccountDeletedBanner>` Permanent-delete-now button fill | True destructive action — irreversible hard-delete. Same visual weight as ConfirmDialog confirm button (already destructive) |
| `<ConfirmDialog>` confirm button when invoked from Permanent-delete-now | Inherited (Type-DELETE variant from Phase 02.2 D-S3 — no change) |

### Accent NOT for (UNCHANGED + new exclusions)

- PollingBadge variants — see rule above. Color lives in the icon, not the chrome.
- `<RefreshNowButton>` idle state — uses `--color-text-muted` (neutral icon). Hover state darkens slightly toward `--color-text`. Do NOT highlight refresh in accent — clicking it should feel routine, not exceptional.
- `<RefreshNowButton>` cooldown-disabled state — uses `--color-text-muted` at 0.5 opacity, NOT destructive. The button is paused, not in error.
- QuotaKeyTable rows — use no fill; the status pill is the ONLY colored element per row. Plain rows preserve scan speed.
- QuotaAuditList — visually mirrors `<AuditRow>` (zero accent fill); it's an INSERT-only log surface where every row reads the same regardless of action verb (color-coding audit verbs would imply some are more important than others — we don't make that claim in 3.0).
- `<AdminLayout>` chrome — DO NOT tint the AppHeader, Nav, or main content area when in admin mode. Phase 6 may revisit if `/admin/*` grows; 3.0 keeps the chrome identical to user-facing pages and uses only the breadcrumb stripe to differentiate.

## Interaction Contracts

### `<PollingBadge>` live state

Props (extends Phase 2.1 placeholder shape — backwards-compatible):
- `event: { kind, lastPolledAt, lastPollStatus, occurredAt, metadata, id }` — full event needed because the badge derives tier from `occurredAt` and renders the refresh-now button bound to `event.id`.
- Hidden for non-pollable kinds — UNCHANGED from 2.1 (`kind ∈ {youtube_video}` for 3.0; `reddit_post` rendering arrives Phase 3.1).

Tier resolution (read-only mirror of `tier-resolver.ts` per CONTEXT Pitfall 7):
- `daysSinceOccurred = (now - occurredAt) / 86400_000`, where `now = Date.now()` at render
- `tier = Active` when `daysSinceOccurred < 1` (0–24h)
- `tier = Cold` when `1 ≤ daysSinceOccurred < 28`
- `tier = Frozen` when `daysSinceOccurred ≥ 28`

Variant resolution (rendered copy):
- If `lastPollStatus IN {not_found, private, auth_error}` → render `Unavailable`, regardless of tier
- Else if `lastPolledAt IS NULL` AND tier=Active → render `polling_badge_manual` ("Manual entry — no polling") for the brief window between paste and first scheduler tick
- Else if tier=Active → `Hot · checked {hoursAgo}h ago`
- Else if tier=Cold AND `daysSinceLastPoll < 2` → `Cold · yesterday`
- Else if tier=Cold → `Cold · {daysAgo}d ago`
- Else if tier=Frozen → `Frozen · refresh to update`

Refresh-now affordance visibility (D-10):
- Visible WHEN `last_polled_at IS NOT NULL` OR tier=Frozen
- Hidden WHEN `last_polled_at IS NULL` AND tier ≠ Frozen (no point in refreshing what was never polled — the scheduler will pick it up)

### `<RefreshNowButton>` interaction

- **Idle state** — refresh icon at `var(--color-text-muted)`. Tap target 44×44; visible glyph 16×16 centered.
- **Click** → `POST /api/events/{id}/refresh-poll` (no body). Optimistically transitions to spinning state immediately.
- **Spinning state** — refresh icon rotates 360° linearly over 1s, repeats. Button is `aria-busy="true"` and `aria-live="polite"` announces `polling_refresh_now_pending` ("Refreshing…"). Disabled (no double-click).
- **On 200/202** — transitions through `polling_refresh_now_done` ("Polled just now") for ~2s, then back to idle (the parent's `invalidateAll()` re-runs the loader and the badge variant updates from server data).
- **On 429** — transitions to cooldown-disabled state. Reads `retry-after` from response (or falls back to computing remaining minutes from `event.metadata.last_user_refresh_at + 5min - now`). Tooltip via `aria-describedby` shows `polling_refresh_now_cooldown_tooltip` ("Wait Xm before refreshing again"). The button auto-re-enables when the cooldown expires (a `setInterval` ticks once per 30s re-evaluating the disable condition; cleaned up on component unmount).
- **On other non-2xx / network** — transitions to idle and renders `polling_refresh_now_error` inline below the badge (not in a toast — toasts don't exist in this app yet; inline `<small role="alert">` matches the InlineError pattern).

Cooldown disabled visual: refresh icon at 0.5 opacity. Cursor `not-allowed`. Same hit area (44×44) — the disabled button still receives focus + the tooltip on hover/focus.

### `<BackfillPicker>` interaction

- Rendered as a fieldset with `<legend>` (the section title); 5 `<label>` rows, each containing a `<input type="radio">` + the preset name + `<span class="quota-cost">` secondary line.
- Default-selected: `30d` (D-09). Selecting any other preset emits no network call — the choice lives in form state until `Save source` submits the parent `/sources/new` form.
- Below the radio group, a single `<small>` paragraph renders the helper text — its content depends on the currently-selected preset (`backfill_picker_helper_1d` only when `1d` is selected; `backfill_picker_helper_default` for the other four). This avoids stuffing five helper paragraphs into the DOM at once.
- The picker is conditionally rendered: only appears when the parent form's `kind === 'youtube_channel'` AND `auto_import === true`. Toggling `auto_import` off OR switching `kind` collapses the picker AND resets its value to `30d` (D-09 default).
- The chosen value is submitted in the same `POST /api/sources` body as a new field, e.g. `backfill_window: '1d' | '7d' | '30d' | '90d' | 'everything'`. Server-side, the kick-off enqueues the channel-context-backfill job with that window.
- A11y: `<fieldset>` + `<legend>` is the radio-group accessible name; each `<label>` wraps its `<input>` so the entire row is the click target (44px tap row on mobile).

### `<AccountDeletedBanner>` Permanent-delete-now CTA activation (DV-6)

Adds a SECOND button to the existing `.actions` row (Restore stays first; Permanently-delete-now sits to its right). On wide viewports both buttons share the row; on narrow viewports they wrap (existing flex-wrap handles this — no media-query change needed).

- **Idle state** — destructive-fill button (matches existing `<ConfirmDialog>` confirm button visual). Label `account_deleted_banner_permanent_delete_button`.
- **Click** → opens `<ConfirmDialog requireText="DELETE" isIrreversible={true}>` (Type-DELETE variant from Phase 02.2 D-S3). Both gates engaged: speedbump checkbox + Type-DELETE input. `confirmLabel` reuses `account_deleted_banner_permanent_delete_button` ("Permanently delete now") for consistency between the banner CTA and the dialog confirm.
- **On confirm** → `DELETE /api/me/account/purge` (no body). UI shows pending state (button disabled, label changes to `Deleting…` — reuses `m.account_deleted_banner_restore_pending` if it exists, else add `m.account_deleted_banner_permanent_delete_pending`). On 200 response: client-side `signOut()` + redirect to `/` via `goto('/', { invalidateAll: true })` — same flow as the existing handleSignOut in `+layout.svelte`.
- **On 4xx/5xx/network** → `restoreError`-equivalent state on the banner (existing `restoreError` Svelte state extended OR a parallel `purgeError` — planner picks). Renders `account_deleted_banner_permanent_delete_failed` inline below the banner. Same red text styling as the existing `.error` rule.

The Restore button is NOT disabled while Permanent-delete-now is in flight — the user can theoretically race them. Server-side `purgeAccount` and `restoreAccount` are mutually exclusive at the row-lock level (Phase 02.2 services); whichever wins is fine. The UI does not need a client-side mutex.

### `/admin/quota` interaction

- SvelteKit `+page.server.ts` loader fetches `/api/admin/quota` (admin-allowlist gated). Response shape: `{ today: 'YYYY-MM-DD' (Pacific), keys: QuotaKeyRow[], audit: AuditEntry[] }`.
- If the user is NOT in `ADMIN_EMAIL_ALLOWLIST`, the loader receives 404 from the API and SvelteKit renders the standard 404 page (the app's existing 404 handler — no custom admin-deny page in 3.0). Self-host parity assertion: smoke test boots image with empty allowlist, hits `/admin/quota`, asserts 404 (D-16 + D-NEW Smoke).
- AdminLayout breadcrumb renders ABOVE the `<PageHeader>` in the `/admin/*` route group. Sticky behavior: NOT sticky (the breadcrumb is informational; sticking it competes with the existing chrome+PageHeader stack and adds no value at /admin/quota's typical scroll depth).
- QuotaKeyTable is a plain `<table>` (no virtualization — N keys is bounded by `SERVICE_YOUTUBE_API_KEYS.length`, typically 1–3 per CONTEXT Specifics "Google ToS limits").
- QuotaAuditList renders the last 50 entries plain — no pagination, no infinite scroll. Phase 6 may extend.

### `/sources/new` second step layout

The existing `/sources/new` form is single-page (Phase 2.1 design). Phase 3.0 inserts the `<BackfillPicker>` ABOVE the existing `Save source` submit button, with a horizontal `<hr>` (`border-top: 1px solid var(--color-border)`) separating it from the kind/owner/auto-import fields above. The picker only renders when the kind/auto-import combination warrants it (see Interaction Contract above) — when collapsed, the `<hr>` collapses too (no orphan separator).

There is NO multi-step form scaffolding (no "Next →" / "Back ←"). The picker is a conditional section within the same single-page form. This matches Phase 2.1 D-09 ("Single CTA pattern for new resources").

## Accessibility Floor (delta)

**UNCHANGED Phase 2 floor:** `:focus-visible` 2px accent outline + 2px offset; 44px touch target on icon-only buttons; semantic landmarks; respects `prefers-reduced-motion`; respects `prefers-color-scheme` via the data-theme model.

**3.0 deltas:**

- `<PollingBadge>` keeps `role="status"` from Phase 2.1 (announces variant changes via `aria-live="polite"` once mounted; no announcement on initial render — that's a regression risk from setting `aria-live` too eagerly, so it's `polite` not `assertive`).
- `<RefreshNowButton>` requires `aria-label` (icon-only); during pending state, sets `aria-busy="true"` and the parent `<PollingBadge>` `aria-live` announces `polling_refresh_now_pending`.
- The cooldown tooltip uses `aria-describedby` pointing at a `<span class="sr-only">` (visually-hidden) carrying the cooldown copy. Keyboard users (Tab focus to disabled button) hear the tooltip via screen reader.
- The spinning animation on `<RefreshNowButton>` MUST honor `@media (prefers-reduced-motion: reduce)` — collapse to a static "in progress" state (e.g., the icon at full opacity with `aria-busy="true"` but no rotation). Pattern: wrap the rotation in `@media (prefers-reduced-motion: no-preference) { ... }`.
- `<BackfillPicker>` requires `<fieldset><legend>` markup so the radio group's accessible name reads "Initial backfill" (not "1 day, 7 days, …"). Each `<label>` wraps its `<input type="radio">` so the entire 44px row is the click target.
- `<ConfirmDialog requireText="DELETE">` from Phase 02.2 D-S3 — UNCHANGED. Native `<dialog>` showModal() focus-trap, Escape-to-close, focus default on Cancel — all inherited.
- `<AccountDeletedBanner>` Permanent-delete-now CTA is keyboard-reachable via Tab from the existing Restore button (DOM order matters — Restore is rendered first, Permanently-delete-now second). Both share the existing 44px height contract.
- `/admin/quota` page renders a single `<main>` with proper `<h1>` / `<h2>` hierarchy. AdminLayout breadcrumb is `<nav aria-label="Admin mode">` so screen readers announce its purpose.
- All new copy uses sentence case (no SHOUTING). Status pills `OK`, `80% throttle — Cold paused`, `95% throttle — Active paused` are intentional fragments — they fit the dense table context, NOT a sentence.
