## Setup (one-time before any assertion)

Local dev does NOT use real Google OAuth — it uses `oauth2-mock-server` on
`localhost:9090` (matches `OAUTH_DISCOVERY_URL` in `.env`). To sign in
through the browser you need to run the mock alongside the dev server.

1. **Confirm `.env.local` exists and contains:**
   ```
   SERVICE_YOUTUBE_API_KEYS=<your disposable test key>
   ADMIN_EMAIL_ALLOWLIST=admin@test.local
   ```
   (`admin@test.local` is the canonical `@test.local` domain used everywhere
   in the repo's integration test fixtures. The mock server below mints this
   email by default — keep both sides aligned.)

2. **Terminal 1 — start the mock OAuth server:**
   ```
   pnpm dev:mock-oauth
   ```
   It logs `mock OAuth running on http://localhost:9090` and stays
   foreground. Default claims: `sub=admin-local`, `email=admin@test.local`,
   `name="Admin Local"`. Override via `pnpm dev:mock-oauth -- --email
   user@test.local --sub user-x` if you need a non-admin user for
   assertions 2 and 9 (cross-tenant 404 and soft-delete flow).

3. **Terminal 2 — start the dev server:**
   ```
   pnpm dev
   ```
   Vite on `http://localhost:5173`. SvelteKit picks up `.env` then
   overlays `.env.local`.

4. **Sign in** at `http://localhost:5173` via "Sign in with Google" button.
   You'll be redirected to `localhost:9090`, the mock returns a valid
   id_token with `email=admin@test.local`, Better Auth lands you back
   in the app as that user.

5. Have a **YouTube channel URL** ready (e.g.
   https://www.youtube.com/@GoogleDevelopers) for assertions 3-7 and 10.

6. Have a **YouTube video URL with a known timestamp** (e.g. one ~5 days
   old, one ~30 days old) for the tier-state assertions 3-5.
