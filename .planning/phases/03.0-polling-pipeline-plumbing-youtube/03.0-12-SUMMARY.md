## Accomplishments

- **DV-6 activation**: `AccountDeletedBanner.svelte` un-hides the Permanent-delete-now CTA from Phase 02.2-04 (PUTOFF marker removed). Click → `<ConfirmDialog requireText="DELETE" isIrreversible={true}>` (Phase 02.2 D-S3 pattern reused verbatim — both Type-DELETE input AND speedbump checkbox engaged) → `DELETE /api/me/account/purge` → `signOut()` + `goto('/', {invalidateAll: true})`. Inline error via `m.account_deleted_banner_permanent_delete_failed()` on 4xx/5xx. The session-row cascade in the purge tx means follow-up requests with the pre-purge cookie return 401 by construction; the explicit `signOut()` is belt-and-suspenders for Better Auth's client-side state.

- **D-09 BackfillPicker**: New component `BackfillPicker.svelte` ships 5 preset rows (`1 day` · `7 days` · `30 days` *(default-selected)* · `90 days` · `Everything`) with cost hints (`≈ 1 quota unit` for the four day-presets; `up to ≈ 20 quota units (one-time)` for Everything). Helper paragraph below switches: `1d` selected → "Picks up only new content from this moment — past videos won't be imported"; otherwise → "30 days fits most active devlogs without spending much quota." `<fieldset>` + `<legend>` markup gives the radio group an accessible name; each `<label>` row is the 44px tap target.

- **/sources/new wiring**: Conditional render gate `showPicker = $derived(selectedKind === 'youtube_channel' && autoImport)`; `$effect` resets `backfillWindow` to `'30d'` when the picker collapses. The submission body conditionally includes `backfillWindow` — the server's optional-with-service-default contract handles both shapes cleanly.

- **Service backfill enqueue**: `createSource` accepts a new optional `backfillWindow` param. After the load-bearing INSERT + `source.added` audit, IF (`row.kind === 'youtube_channel'` AND `row.autoImport === true`), enqueues ONE `YOUTUBE_CHANNEL_CONTEXT_BACKFILL` job carrying `{sourceId, userId, handleUrl, backfillWindow}` with `singletonKey: source-${row.id}`. Plan 09's worker handler reads `job.data.backfillWindow` and sizes the snapshot-seeding window. Fire-and-forget: a pg-boss outage logs at WARN and does NOT block source creation.

- **POST /api/sources schema extension**: `backfillWindow` enum (`'1d' | '7d' | '30d' | '90d' | 'everything'`) added as optional. Service-layer default keeps the HTTP contract minimal.

## Decisions Made

- **SSR-render unit tests over Playwright** for both new components. The ConfirmDialog modal-flow is already covered by the Phase 02.2 D-S3 tests; here we only assert the new prop wiring + new copy. The HTTP-boundary integration tests cover the click → fetch → cascade chain without needing a real browser.
- **`tests/integration/sources-backfill.test.ts`** as a NEW file (plan said `sources.test.ts` but the repo has `data-sources.test.ts`). Keeps the `vi.mock('queue-client')` scoped — adding it to the existing `data-sources.test.ts` would have unnecessarily mocked pg-boss across 30+ unrelated tests.
- **Service-layer default for `backfillWindow`** instead of zod-layer default. The BackfillPicker always sends an explicit value; the service-layer default exists for direct callers (tests, future internal use). Keeps the HTTP boundary minimal.
- **`singletonKey: source-${row.id}`** (distinct from the ingest trigger's `channelId` key). Different identity scope: source row creation is per-(user, handle), so deduping by source id is the natural granularity.
