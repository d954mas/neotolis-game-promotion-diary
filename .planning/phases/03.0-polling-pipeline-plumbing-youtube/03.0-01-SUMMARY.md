## Decisions Made

- **`ALTER TYPE ... ADD VALUE IF NOT EXISTS` for all 5 audit verbs.** Drizzle-kit's default emits unconditional `ADD VALUE` statements; we hand-edit to match the Plan 02.2-01 / 02.1-27 / 02.1-12 precedent so a re-run of the migration on a partially-applied DB does not error. This is critical for the advisory-locked migration runner — if migrate() retries after a transient failure, idempotency guards prevent a half-applied state.
- **pgboss queue cleanup gated on schema existence.** The plan template ended with an unconditional `DELETE FROM pgboss.queue WHERE name IN ('poll.hot', 'poll.warm')`. pgboss creates its own schema at runtime via `boss.start()`, not at migrate time, so the unconditional DELETE would fail on fresh test DBs (where pgboss has not yet booted). Wrapped in `DO $$ BEGIN IF EXISTS (information_schema.schemata WHERE schema_name = 'pgboss') AND EXISTS (information_schema.tables …) THEN DELETE … END $$`. This is a Rule 1 / Rule 3 deviation: the literal plan would have broken integration tests on first run.
- **`events_user_kind_ext_active_unq` added alongside (not as replacement for) `events_user_kind_source_ext_unq`.** The existing index keys off `(user_id, kind, source_id, external_id)` partial `WHERE source_id IS NOT NULL AND external_id IS NOT NULL` — that's the auto-import dedup index. The new index keys off `(user_id, kind, external_id)` partial `WHERE external_id IS NOT NULL AND deleted_at IS NULL` — that's the refresh-poll idempotency index (catches manual paste collisions where source_id is NULL). Different semantics, both retained. Plan acceptance criteria did not specify a drop of the old index; we kept it.
- **ESLint allowlist additions as explicit-intent documentation.** Queries against `youtubeVideoSnapshots` / `youtubeChannelMetadataCache` / `youtubeServiceQuotaUsage` do not currently trip the rule (they are not in TENANT_TABLES). Allowlist entries are added defensively — if a future refactor accidentally adds these identifiers to TENANT_TABLES, the allowlist is the explicit override that keeps public-data semantics legible to reviewers. Comment block in the rule file documents the rationale.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] pgboss schema-existence guard on the legacy-queue DELETE**
- **Found during:** Task 2 (migration generation)
- **Issue:** The plan specified an unconditional `DELETE FROM pgboss.queue WHERE name IN ('poll.hot', 'poll.warm')` appended to the migration. pgboss creates its own schema at runtime via `boss.start()`, not at migrate time, so the unconditional DELETE would fail on fresh test DBs (where pgboss has not yet booted) with `ERROR: schema "pgboss" does not exist`.
- **Fix:** Wrapped the DELETE in a `DO $$ BEGIN IF EXISTS (information_schema.schemata) AND EXISTS (information_schema.tables) THEN DELETE … END $$` block. Production behaviour is unchanged (pgboss schema is present after first deploy boot); test-DB behaviour is now safe.
- **Files modified:** `drizzle/0010_phase03_baseline.sql`
- **Verification:** `pnpm db:check` zero drift; integration test for `idempotent on second boot` would pass on fresh DB (verified via reasoning — DB unavailable in this dev environment, see Issues Encountered below).
- **Committed in:** `f11f43e`

**2. [Rule 2 - Missing Critical] `IF NOT EXISTS` on ALTER TYPE ADD VALUE statements**
- **Found during:** Task 2 (drizzle-kit codegen review)
- **Issue:** Drizzle-kit emitted `ALTER TYPE "public"."audit_action" ADD VALUE 'quota.service_throttled';` without the `IF NOT EXISTS` guard. Plan 02.1-12 / 02.1-27 / 02.2-01 precedent uses `IF NOT EXISTS` for idempotency on advisory-locked migration retries. Without the guard, a transient migrate failure followed by a retry produces a `ERROR: enum value "quota.service_throttled" already exists` and blocks subsequent forward progress.
- **Fix:** Hand-edited the migration to add `IF NOT EXISTS` to all 5 ALTER TYPE statements; documented the precedent inline.
- **Files modified:** `drizzle/0010_phase03_baseline.sql`
- **Verification:** Pattern matches three prior migrations (0001, 0006, 0008); `pnpm db:check` zero drift.
- **Committed in:** `f11f43e`
