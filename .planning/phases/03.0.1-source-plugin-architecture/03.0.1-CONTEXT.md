# Phase 03.0.1: Source Plugin Architecture - Context

**Gathered:** 2026-05-08
**Status:** Ready for planning

<domain>
## Phase Boundary

Restructure the YouTube implementation that landed in Phase 03.0 into a per-source plugin architecture so that future sources (Reddit, Twitter, Telegram, DTF, Pikabu, ...) drop in as new sub-folders without editing cross-source plumbing. The phase delivers:

1. All YouTube-prefixed code moved into `src/lib/sources/youtube/{server,ui}/` with co-located schema, http wrapper, quota tracker, tier resolver, snapshot writer, handlers, route, and UI components.
2. A SourceRegistry so worker handlers and routes dispatch by `source.kind` via `getAdapter(kind)` / `getAdapterUI(kind)`.
3. A widened `DataSourceAdapter` contract carrying credentials/quota/observability mechanics fully inside the adapter.
4. A standardized error taxonomy (`AdapterError`) and observability API exposed by every adapter.
5. A generic `POST /api/sources/:id/refresh-content` endpoint that exercises the new contract end-to-end, plus a "Pull new content" UI button on `/sources/[id]`.
6. A `SOURCE-REFERENCE.md` document describing the canonical source plugin layout and a step-by-step "how to add a new source" guide.

Behavioral identity for YouTube is preserved — existing integration + smoke tests pass unchanged. The phase is structural: cleaner module boundaries + standardized contract, no new user-facing features beyond the refresh-content button.

The phase explicitly does NOT introduce per-user credentials (Phase 6 trigger), Reddit/Twitter/etc adapters (Phase 03.1+), or schema-level de-duplication of snapshot tables across kinds.

</domain>

<decisions>
## Implementation Decisions

### Adapter scope (D-01..D-04)
- **D-01:** Adapter scope is **Thick** — each adapter is fully self-contained (HTTP, parsing, persistence, eligibility, cooldowns, observability all live inside `sources/<kind>/`). Cross-source services never switch on `source.kind`.
- **D-02:** Each source plugin uses a **dual-tree layout**: `sources/<kind>/server/` (server-only code, schemas, handlers, http) and `sources/<kind>/ui/` (Svelte components, props mappers).
- **D-03:** UI consistency is achieved via a **standardized props mapper** pattern: each adapter exposes `toCardProps(event) → { thumbnail, title, subtitle, badge, metrics[], href }`. A universal shell component (`src/lib/components/EventCard.svelte`) renders the layout; per-source mappers fill the slots. Same pattern applies to `SourceCardRow`, `SourceDetailHeader`, `DetailMetricsChart`, `QuotaTab`.
- **D-04:** **Escape hatch** for unique layouts: an adapter MAY expose a full Svelte component (e.g. `EventCard.svelte`) that bypasses the standardized shell. Default = mapper. Override = component. Documented but discouraged unless the standard layout cannot accommodate the kind.

### Credentials and quota (D-05..D-09)
- **D-05:** v0.1 ships **operator-only credentials everywhere**. No per-user OAuth flow exists in 03.0.1. YouTube uses static API keys from operator's env (existing). Reddit/Twitter (when they land in later phases) use **app-only OAuth** — operator registers app, client_credentials grant, adapter handles refresh internally. DTF/Pikabu use scraping with operator's User-Agent. Per-user credential override is deferred to Phase 6 and is a pure adapter-internal change at that time (no contract surface change required).
- **D-06:** **Adapter encapsulates auth/quota mechanics**. Worker handlers, routes, and cross-source services do NOT know envelope-vs-OAuth-vs-scrape. They call `adapter.pollContent(source, since, ctx)` / `adapter.pollStats(ids, ctx)` and the adapter resolves credentials internally via `pickCredentials(ctx)`.
- **D-07:** **`AdapterContext`** is `{ userId?: string | null; origin: "cron" | "user" }`. `userId` is useful for audit/logging now (and for Google's `quotaUser` per-user fingerprint that already exists in YouTube's poll-user path). `origin` drives rate-limit budget split (see D-09). Phase 6's user-override hook is `pickCredentials(ctx)` extending in adapter without contract change.
- **D-08:** Each adapter exposes **standardized observability API** (`adapter.observability`):
  - `auth: { kind, requiresUserSetup, isOperatorConfigured? }` — for /admin/quota and /sources/[id] connection-status badges.
  - `quota.getDailyStats(date) → { unitsUsed, dailyLimit, pctOfDaily, throttleState, keys?, costEstimateUsd? }` — admin-panel dashboard data.
  - `quota.getRecentAudit(limit) → AuditEntry[]` — admin-panel audit feed (per-kind filter).
  Per-source quota schemas live in `sources/<kind>/server/schema/` (e.g. `youtube_service_quota_usage` stays YouTube-specific). Admin panel multi-source via tabs/sections (`sources/<kind>/ui/QuotaTab.svelte`).
- **D-09:** **Rate-limit budget reserved for user actions**. Each adapter HTTP wrapper splits rate budget into `cron pool (~80-90%)` and `user pool (~10-20%, reserved)`. Defaults: YouTube 9000/1000 daily envelope, Reddit 54/6 per minute, Twitter 80/20 percent split, scraping 80/20 self-imposed. User-initiated calls (`ctx.origin = "user"`) cannot be starved by cron-heavy days. Adapter encapsulates the policy; can evolve (burst-allow, time-of-day shifts, borrow-from-cron) without contract change.

### Queue topology (D-10..D-12)
- **D-10:** **Per-kind queues**. Each source plugin owns its queue names, cron schedule, handlers, concurrency limits, and rate-limiting. The cross-source orchestrator (`src/worker/index.ts`) does only `for (adapter of allAdapters) adapter.registerQueues(boss)`. Add Reddit = create `sources/reddit/server/handlers/` and register queues; zero edits in `worker/index.ts` beyond one push to `allAdapters`.
- **D-11:** **Queues split into cron / user / backfill** per kind:
  ```
  <kind>.poll.cron      ← scheduler-driven batch polling (Active/Cold tier)
  <kind>.poll.user       ← user-initiated refresh-now (per event)
  <kind>.backfill.user   ← user-initiated "Pull new content" (per source)
  <kind>.<extras>         ← kind-specific (youtube.quota_reset, youtube.rehab, ...)
  ```
  Independent worker subscriptions per queue. User-initiated jobs are NOT blocked by cron batch on the queue level. Rate-limit budget shared across queues at the adapter HTTP layer (see D-09 for the user reserve).
- **D-12:** **No truly shared async queues exist** in this architecture. Audit log writes are synchronous (`writeAudit()` INSERT). Cross-source DB CRUD is synchronous. Only async work (polling, backfill, rate-limited HTTP) goes through queues, and all of it is per-kind.

### Failure model (D-13)
- **D-13:** **Standardized 5-category `AdapterError` taxonomy** for v0.1:
  | Category | Examples | System action | UI surfacing |
  |----------|----------|---------------|--------------|
  | `transient` | 5xx, network timeout | pg-boss retry with backoff | None (silent) |
  | `rate-limited` | 429, quotaExceeded 403 | Adapter HTTP wrapper waits; cron defers if budget exhausted | /admin/quota throttled badge |
  | `not-found` | Video deleted, post removed | Mark `event.status = unavailable`; tier → Frozen | "No longer available" banner on /events/[id] |
  | `permanent` | ToS block, scraping HTML changed | Mark unavailable, stop polling | /admin/quota error + dev attention |
  | `operator-issue` | No keys configured, key revoked, OAuth secret rotated | Log + /admin/quota banner | /admin/quota: "Operator needs to fix X" |

  Schema additions: `data_sources.needs_reconnect: boolean`, `data_sources.last_error_at: timestamp | null`, `data_sources.last_error_kind: text | null`. Phase 6 adds a 6th category `user-auth` when per-user credentials land.

### Folder layout (D-14..D-15)
- **D-14:** **Canonical source plugin layout**:
  ```
  src/lib/sources/
  ├── adapter.ts                    ← Shared DataSourceAdapter interface
  ├── registry.ts                    ← getAdapter(kind) — server-side
  ├── registry-ui.ts                  ← getAdapterUI(kind) — client-side
  └── youtube/
      ├── server/
      │   ├── adapter.ts              ← Implements interface
      │   ├── credentials.ts           ← pickCredentials(ctx)
      │   ├── http.ts                   ← chargedFetch + rate-limit token bucket
      │   ├── url.ts                    ← parseUrl(url)
      │   ├── observability.ts          ← getDailyStats, getRecentAudit
      │   ├── schema/
      │   │   ├── channels.ts
      │   │   ├── videos.ts
      │   │   ├── video-snapshots.ts
      │   │   ├── service-quota-usage.ts
      │   │   └── metadata-fetch-log.ts
      │   └── handlers/
      │       ├── poll-active-cron.ts
      │       ├── poll-cold-cron.ts
      │       ├── poll-user.ts
      │       ├── channel-context-backfill.ts
      │       ├── quota-reset.ts
      │       └── rehab-unavailable.ts
      └── ui/
          ├── card-props.ts             ← toCardProps + toSourceCardProps mappers
          ├── EventCard.svelte           ← (optional override) full custom
          ├── SourceCardRow.svelte
          ├── SourceDetailHeader.svelte
          ├── DetailMetricsChart.svelte
          └── QuotaTab.svelte             ← admin panel kind-specific tab
  ```
  Cross-source schemas (`events`, `data_sources`, `audit_log`, `games`, `event_games`, `game_steam_listings`, `api_keys_steam`, Better Auth tables) STAY in `src/lib/server/db/schema/`. Drizzle config glob extends to `src/lib/sources/*/server/schema/*.ts`. Cross-source services (`data-sources.ts`, `events.ts`, `ingest.ts`, `purge-account.ts`, `audit-read.ts`) STAY in `src/lib/server/services/`. SvelteKit routes stay in `src/routes/` (SvelteKit convention) and import from `sources/<kind>/ui` via the UI registry.
- **D-15:** **URL detection** is `iterate adapter registry, first match wins`. Each adapter exposes `parseUrl(url) → { kind, externalId, metadata? } | null`. Universal /events/new route iterates `for (adapter of allAdapters) await adapter.parseUrl(url)` and uses first non-null result. Registration order = priority. Unknown URL → 422 "Not supported by any registered source".

### Migration approach (D-16)
- **D-16:** **Phased migration** — 8-10 incremental commits, each independently verifiable + CI green. Big-bang rejected to preserve review clarity even though no prod data risk exists. Approximate sequence:
  1. Add `sources/` directory + base interfaces (no moves yet)
  2. Move schemas (`db/schema/youtube-* → sources/youtube/server/schema/`) + drizzle config update
  3. Move adapter + http (`integrations/youtube-* → sources/youtube/server/`)
  4. Move services (`services/youtube-* → sources/youtube/server/`)
  5. Move handlers (`worker/handlers/youtube-* → sources/youtube/server/handlers/`)
  6. Move route (`http/routes/youtube-metadata.ts → sources/youtube/server/route-metadata.ts`)
  7. Refactor cross-source workers (poll-active/cold/user/rehab) to dispatch via registry; introduce per-kind queue split
  8. Add new contract methods (observability API, AdapterContext.origin, rate reserve, AdapterError taxonomy, parseUrl)
  9. UI dual-tree (move EventCard et al. → `sources/youtube/ui/`); standardized props mapper
  10. Add `POST /api/sources/:id/refresh-content` endpoint + UI button
  11. SOURCE-REFERENCE.md
  Each commit: typecheck 0 errors, unit + integration green, lint clean.

### SOURCE-REFERENCE.md scope (D-17)
- **D-17:** **Sections 1-7, no `_template/` scaffolding files**. The canonical YouTube implementation IS the live reference; contributor copies from `sources/youtube/` directly. Document covers:
  1. Overview — what is a source plugin, why this architecture
  2. Folder structure — where files live (server / ui / schema / handlers)
  3. Step-by-step "Adding a new source" walkthrough
  4. Common patterns — chargedFetch with token bucket, OAuth refresh, snapshot UPSERT, URL parsing
  5. Anti-patterns — kind switch in cross-source code, duplicating fetchWithTimeout, skipping observability, ignoring rate-limit reserve
  6. Testing — unit (HTTP wrapper, parseUrl, mappers), integration (full adapter against real DB, mocked HTTP), smoke (production image vs mock API)
  7. Phase 6 future — placeholder section describing how user-credentials will plug in (no implementation scope)

### Claude's Discretion
- Specific file naming inside `sources/youtube/server/handlers/` may diverge from the example in D-14 if a clearer name surfaces during execution (e.g. `poll-active.ts` vs `poll-active-cron.ts`); the rule is "1 handler file per queue, name matches the queue's purpose".
- The exact concurrency / cron schedules per queue (e.g. `youtube.poll.user` teamSize 1 vs 2) are tuning parameters left to plan-phase / execution; defaults from Phase 03.0 carry forward unchanged.
- Whether `<UniversalEventCard>` lives in `src/lib/components/` or `src/lib/sources/components/` is a style call; either works as long as the wrapper is universal.
- Test mocking strategy for unit-level adapter tests (vi.mock vs dependency injection vs real DB) — pick whichever pattern Phase 03.0 already established for the equivalent layer.

## Existing Code Insights

### Reusable Assets
- **`chargedFetch` / `fetchWithTimeout`** (`integrations/youtube-http.ts`) — already centralized post-build review. Keep + move into `sources/youtube/server/http.ts`. Reddit will get its own version with token bucket + OAuth-refresh layered on top.
- **`pickKeyForJob` + `hashApiKeyId`** (`services/youtube-quota-tracker.ts`) — envelope quota helpers; YouTube-specific. Move into `sources/youtube/server/credentials.ts` (pickCredentials wrapper) + `sources/youtube/server/quota.ts` (counter + throttle state).
- **`youtubeChannelAdapter`** (`integrations/youtube-channel-adapter.ts`) — current adapter with `pollContent` / `pollStats` / `pollStatsByVideoId`. Refactor to implement the widened contract (parseUrl, observability, AdapterError taxonomy).
- **`writeSnapshot`** (`services/youtube-snapshot-writer.ts`) — currently writes to `youtube_video_snapshots` and increments quota counter. Either move into `sources/youtube/server/snapshots.ts` (D-01: adapter owns persistence) OR keep cross-source if it parameterizes by adapter (D-01 says Thick → adapter owns it).
- **`PollingBadge`, `RefreshNowButton`** (`src/lib/components/`) — UI components today are YouTube-aware. Per D-02, these become universal SHELL + per-source CONTENT via standardized props mapper.
- **`AdminQuotaPage`** (`src/routes/admin/quota/`) — per-kind tabs via `getAdapterUI(kind).QuotaTab`.

### Established Patterns
- **Tenant scoping** (CLAUDE.md / AGENTS.md): every user-owned table query filters by `userId`; ESLint `tenant-scope/no-unfiltered-tenant-query` rule. Cross-source allowlist (e.g. `youtube_service_quota_usage`) carries inline disable + comment. Maintain through the refactor.
- **DTO discipline**: every entity has `to<Entity>Dto` that strips ciphertext and tenant ids. Per-source schemas need their own DTOs in `sources/<kind>/server/dto.ts` if they expose data to UI.
- **Audit INSERT-only invariant** (Migration 0019 trigger). Every adapter that emits audit (e.g. `quota.service_throttled`) uses `writeAudit` directly — no through-queue audit pattern.
- **Forward-only migrations** + `drizzle-kit migrate` at boot under advisory lock. Schema moves require corresponding migrations IF they rename tables; if they only move TS source files (table names unchanged), no migration needed.
- **pg-boss queue pattern** (Phase 03.0 Plan 09): scheduler-tick subscriptions, `boss.work(queue, opts, handler)`, `singletonKey` for dedup.

### Integration Points
- **`src/worker/index.ts`** — bootstrap that subscribes all queues. After refactor: iterates `allAdapters`, calls `adapter.registerQueues(boss)`. Single-line change per new source plugin.
- **`src/scheduler/index.ts`** + **`scheduler/enqueue.ts`** — cron triggers. Refactor to iterate adapters and call `adapter.scheduleCronTicks(scheduler)` (or similar).
- **Drizzle config** (`drizzle.config.ts`) — glob extends to include `sources/*/server/schema/*.ts`. No table renames in this phase.
- **SvelteKit routes** (`src/routes/`) — pages stay where they are; import `getAdapterUI(kind)` for per-kind components.

### Creative Options
- **Test scaffolding** — Phase 03.0 has Wave-0 placeholder pattern (every later task lands into a pre-existing test). 03.0.1 can do the same: PR #1 lands `sources/_smoke.test.ts` with named placeholder cases, later commits flip them live as adapter pieces land.
- **Drizzle schema discovery** — instead of glob, can re-export from a `sources/<kind>/server/schema/index.ts` and mount in `src/lib/server/db/schema/index.ts`. Either works.
