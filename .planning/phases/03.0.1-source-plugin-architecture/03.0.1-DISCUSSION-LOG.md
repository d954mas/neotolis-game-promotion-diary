## Adapter scope

| Option | Description | Selected |
|--------|-------------|----------|
| Thin | Adapter = HTTP+parse only; persistence/eligibility/cooldowns in shared services with switch-by-kind | |
| Thick | Adapter owns everything — HTTP, parse, persistence, eligibility, cooldowns, observability | ✓ |
| Middle | Adapter HTTP+parse + declarative metadata (snapshotTable, mappers); shared service uses metadata for generic persistence | |

**User's choice:** Thick.
**Notes:** User pushed back on initial Thin / Middle framing — wanted to discuss. Walked through how YouTube/Reddit/Twitter diverge across HTTP, parsing, storage. User's vision crystallised: "common pipeline for user-facing actions + per-source plugin with everything kind-specific (HTTP, parse, store, render) inside". Confirmed Thick + dual-tree (server/ + ui/) per source. UI consistency via standardized props mapper pattern: universal shell component renders layout, per-source `toCardProps()` mapper fills standardized slots ({thumbnail, title, subtitle, badge, metrics, href}). Escape hatch: adapter MAY expose a full Svelte component instead of mapper for unique layouts (Twitter quote-tweet nested cards as the canonical example). Same pattern for SourceCardRow, SourceDetailHeader, DetailMetricsChart, QuotaTab.

## Credentials model

| Option | Description | Selected |
|--------|-------------|----------|
| Caller orchestrates | Worker handler / route knows "YouTube envelope, Reddit OAuth" and passes credentials to adapter | |
| Adapter resolves | Adapter encapsulates auth mechanics; worker calls adapter.pollStats(ids) blind | ✓ |
| Pluggable AuthProvider | Generic strategy interface for future-proofing | |

**User's choice:** Adapter resolves, with several rounds of follow-up.
**Notes:** User initially worried the adapter would become a black box. Walked through that adapter encapsulates *mechanics* but exposes *standardized observability API* — `auth.kind`, `auth.requiresUserSetup`, `auth.isOperatorConfigured?`, `quota.getDailyStats(date)`, `quota.getRecentAudit(limit)`. Per-source quota schemas live in sources/<kind>/server/schema/ (e.g. youtube_service_quota_usage stays YouTube-specific). Admin panel multi-source via per-kind tabs that consume each adapter's `observability.quota.getDailyStats()` output.

User also pushed for clarity on auth-protocol nuances. Clarified that:
- YouTube: static API key (no OAuth needed for our read-only use).
- Reddit / Twitter: OAuth-required, but **app-only OAuth** (operator-shared client_credentials grant) works for read-only data — no per-user OAuth flow needed in v0.1.
- DTF / Pikabu: scraping (no auth at all).
- v0.1 ships **operator-only credentials everywhere**; per-user override deferred to Phase 6.

User asked if planning the per-user-override "open door" cost anything now. Initial answer leaned "leave open door, ~30 lines free". User pushed back to verify. Reconsidered: door-opening reduces to (a) `userId` in AdapterContext (already needed for `youtubeQuotaUser` fingerprint and audit/logging) + (b) `pickCredentials(ctx)` accepting that ctx. Cost is ~1 line + 1 comment. Phase 6 expansion is then a pure adapter-internal change with no contract surface. Locked open-door variant.

User's question about how user-credentials would affect each path mapped naturally: user-initiated actions (refresh-now, paste, pull-new) use user's key in Phase 6; cron uses operator's. v0.1 = all operator. AdapterContext carries `origin: "cron" | "user"` — also drives rate-limit budget reservation (see Queue topology section).

Pitfalls explicitly documented in CONTEXT.md and SOURCE-REFERENCE: OAuth refresh complexity, rate-limit overlap, scraping fragility, ToS compliance, OAuth callback URL config (SaaS vs self-host), token leak (envelope-encrypt or pino-redact).

## Folder layout

| Option | Description | Selected |
|--------|-------------|----------|
| Flat: sources/youtube/{adapter.ts, http.ts, schema.ts, ...} | Single file per concern at folder root | |
| Nested: sources/youtube/{server/, ui/}/ with sub-dirs (schema/, handlers/) | Dual-tree by execution side | ✓ |
| Single index.ts re-export only, internal layout free | Plugin author decides their own internal layout | |

**User's choice:** Nested dual-tree.
**Notes:** Follows from Thick scope. Server-side: `server/{adapter.ts, credentials.ts, http.ts, url.ts, observability.ts, schema/, handlers/}`. UI-side: `ui/{card-props.ts, EventCard.svelte (optional), SourceCardRow.svelte, SourceDetailHeader.svelte, DetailMetricsChart.svelte, QuotaTab.svelte}`. Cross-source registry / interface at `src/lib/sources/{adapter.ts, registry.ts, registry-ui.ts}`. SvelteKit routes stay at `src/routes/` per framework convention; import per-source UI via registry-ui. Drizzle config glob extends to `src/lib/sources/*/server/schema/*.ts`.

## Queue topology

| Option | Description | Selected |
|--------|-------------|----------|
| All shared queues with kind in payload | Single poll.active / poll.cold queue, handler dispatches via registry | |
| Per-kind queues (split into cron / user / backfill) | Each source plugin owns: queue names, cron, handlers, concurrency, rate-limiting | ✓ |
| All per-kind, but one queue per kind (no cron/user split) | youtube.poll.active, reddit.poll.active, etc. but no separate user queue | |

**User's choice:** Per-kind, split into cron/user/backfill.
**Notes:** Multi-step clarification. User initially uncertain about queue concept; walked through pg-boss semantics (queue = job list, worker subscribes, executes async). Walked through scenario where cron batch starts at 12:00, user clicks RefreshNow at 12:00:30 — without separate queues, user's job becomes 51st in line. Solution: separate per-kind queues for cron vs user-initiated work (e.g. `reddit.poll.cron`, `reddit.poll.user`, `reddit.backfill.user`). Workers subscribe independently per queue. User-initiated jobs not blocked by cron batch on queue level.

User then asked about rate-limit overlap. Clarified that pg-boss queues control *when* jobs run; rate limiting (60/min Reddit) lives separately in adapter HTTP wrapper. Both worker subscriptions share rate budget at the HTTP layer. To prevent cron-heavy days from starving user actions: adapter HTTP wrapper splits rate budget into cron pool (~80-90%) + user pool (~10-20%, reserved). User confirmed this. Defaults: YouTube 9000/1000 daily envelope, Reddit 54/6 per minute, Twitter 80/20%, scraping 80/20% self-imposed. Phase 6 may evolve (burst-allow, time-of-day shifts, borrow-from-cron) — adapter-internal change, no contract impact.

Audit log is synchronous (`writeAudit()` INSERT directly), not queued — clarified after user asked "what could be shared". No truly shared async queues exist in this architecture; all async work is per-kind.

## URL detection / paste flow

| Option | Description | Selected |
|--------|-------------|----------|
| Iterate adapter registry, first match wins | Each adapter exposes parseUrl(url); universal route iterates and returns first non-null | ✓ |
| Central pattern registry | Single regex-to-kind mapping table; O(1) dispatch | |
| Hybrid | Adapter declares static urlPatterns metadata; central matcher reads from registry at startup | |

**User's choice:** Iterate adapter registry.
**Notes:** Direct consequence of Thick scope (plugin owns its URL patterns). adapter.parseUrl(url) returns `{ kind, externalId, metadata? } | null`. Registration order = priority. Unknown URL → 422 "Not supported by any registered source". Simple, minimal, plugin-friendly. With 5-6 sources, iterating 6 patterns is microseconds — no need for central registry optimization.

## Failure mode UX

| Option | Description | Selected |
|--------|-------------|----------|
| 6 categories incl. separate "auth" and "operator-misconfigured" | transient / rate-limited / not-found / permanent / auth / operator-misconfigured | |
| 5 categories, "auth" and "operator-misconfigured" merged | transient / rate-limited / not-found / permanent / operator-issue | ✓ |

**User's choice:** 5 categories.
**Notes:** User asked "what is auth — wrong key?". Clarified that in v0.1 (operator-only credentials), all auth-related failures are operator-action: keys revoked / rotated / app suspended → operator fixes. There is no user-actionable "auth" category in v0.1 because users have no per-source credentials. Phase 6 will add a 6th category `user-auth` ("reconnect your account") when user-override credentials land.

Each category mapped to system action + UI surfacing in CONTEXT.md D-13. Schema additions: `data_sources.needs_reconnect` (boolean), `data_sources.last_error_at` (timestamp), `data_sources.last_error_kind` (text). Existing `events.status` enum extends naturally for `unavailable` / `not_found` outcomes.
