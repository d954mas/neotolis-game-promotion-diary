key-decisions:
  - "Direct INSERT in the handler (NOT createEvent through services/events.ts): the worker handler bypasses createEvent's withQuotaGuard wrapper because that guard is a USER-input throttle (events_per_day cap, ipAddress-tagged). Auto-import / backfill jobs are not user inputs in the quota-billing sense — they're system-emitted side effects of a single button click that's already been audit-logged. Mirrors channel-context-backfill's direct-INSERT pattern. If a future operator hits the per-day cap with an over-eager refresh button, the right fix is a per-source backfill rate-limit on the singletonKey window, not a quota guard inside the worker. Idempotency via pre-INSERT SELECT + DB-level partial unique covers the safety case."
  - "30-day default lookback (NOT data_sources.lastPolledAt): the schema does not carry a per-source last-polled timestamp — polling state lives on youtube_videos per-video (Phase 3.0 post-build refactor 2026-05-06). The Plan-mandated `since = lastPolledAt ?? now-30d` shape was aspirational; the implementation collapses to `since = now-30d` always. Pre-INSERT idempotency below ensures we don't double-create events the cron tick already inserted, so the lookback acts as a content-discovery ceiling rather than a duplication risk. A future enhancement could read max(occurredAt) for events with this sourceId — filed under deferred."
  - "Sole 422 trigger is reddit_account direct INSERT in tests (NOT a behaviour user can reach today): the test file inserts a reddit_account row directly into data_sources to bypass createSource's FUNCTIONAL_KINDS gate. In production the only way to reach the 422 path before Phase 03.1 lands the Reddit adapter is via a forced direct INSERT, but the route's try/catch around getAdapter is the load-bearing guard for the rollout window when an adapter is briefly missing post-Phase-03.1-deploy or a custom self-host operator has registered a kind without wiring its adapter. The 422 path emits AppError (NOT raw Error) so mapErr routes it via the standard wire envelope."
  - "RefreshContentButton sourceKind prop kept (with leading-underscore destructure to silence svelte-check warning): the prop is unused in v0.1 but threaded so future per-kind copy ('Pull new Reddit posts' vs 'Pull new YouTube uploads') can land without a prop-shape change. Removing it would require a breaking change at every call site when Phase 03.1 lights the per-kind copy up. The leading-underscore alias is the project's existing convention for intentionally-unused destructured props (matches the Svelte 5 + svelte-check ergonomics)."
  - "writeAudit AFTER the enqueue (not BEFORE): unlike services/data-sources.ts.softDeleteSource (which audits BEFORE the UPDATE per D-32 forensics ordering), the refresh-content audit fires AFTER backfillSource because the audit metadata REQUIRES result.queue + result.jobId — values only the adapter knows. The trade-off: a transient pg-boss failure between enqueue-success and writeAudit-call would land an enqueued job with no audit row. Acceptable because (a) writeAudit never throws (catches + logs), (b) the user will see the new events appear and re-click is dedup-safe via singletonKey, (c) the security signal forensics need is 'user X requested refresh on source Y at time T'; the queue/jobId is observability nice-to-have, not security-load-bearing."

## Endpoint Behavior (POST /api/sources/:id/refresh-content)

```
Anonymous request:
  → 401 { error: "unauthorized" }                  (tenantScope middleware)

Authenticated, source belongs to caller, kind=youtube_channel:
  → 202 { enqueued: true, queue: "youtube.backfill.user", jobId: "<id>|null" }
  → audit_log row inserted: action='source.refresh_content_requested',
                            metadata={source_id, kind, queue, job_id}
  → pg-boss job enqueued with singletonKey=`backfill-${source.id}`, priority=1

Authenticated, source belongs to other tenant:
  → 404 { error: "not_found" }                     (getSourceById throws NotFoundError)
  → body !match /forbidden|permission/i            (AGENTS.md invariant 2)

Authenticated, source id does not exist:
  → 404 { error: "not_found" }

Authenticated, source soft-deleted:
  → 404 { error: "not_found" }                     (deletedAt !== null branch)

Authenticated, source.kind has no registered adapter:
  → 422 { error: "kind_not_yet_functional" }       (try/catch around getAdapter)
```

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] handler used non-existent `data_sources.lastPolledAt` column**

- **Found during:** Task 1 typecheck after writing handlers/backfill-user.ts
- **Issue:** Plan listing prescribed `since = sourceRow.lastPolledAt ?? new Date(Date.now() - 30d)`. The `data_sources` schema does NOT carry a `last_polled_at` column — polling state lives on `youtube_videos` per-video (Phase 3.0 post-build refactor 2026-05-06). Without the fix, the handler would not typecheck.
- **Fix:** Always use `since = new Date(Date.now() - 30d)`. Pre-INSERT idempotency via `(userId, sourceId, externalId)` SELECT covers the safety case — re-clicking the same source within the 30d window does NOT create duplicate events. Documented in handler header comment + key-decisions section above.
- **Files modified:** `src/lib/sources/youtube/server/handlers/backfill-user.ts`
- **Commit:** `6bff8c9` (Task 1)

**2. [Rule 2 — Missing critical functionality] backfillSource needs `getBoss` import in index.ts (NOT adapter.ts)**

- **Found during:** Task 1 implementation
