<decisions>
## Implementation Decisions

### PR strategy
- **D-01:** One phase-PR onto `master` from `feat/phase-03.0.2-dependency-refresh`. AGENTS.md "Locked stack versions" ("Bumps go through a dedicated PR with a one-line rationale") is preserved in spirit via per-major *atomic commits inside the phase branch*, not via per-major PRs. Memory rule "1 phase = 1 long-lived branch + 1 tracking issue + 1 final PR" stays intact.
- **D-02:** Every commit on the branch MUST land with green CI (`lint-typecheck`, `unit-integration`, `smoke`). No WIP commits, no "fix lint in next commit" intermediate states. If a bump cannot achieve green CI by itself, fix-up commits land in the same atomic unit (one logical commit may be `chore(deps): bump X to Y` + an immediate follow-up `fix(03.0.2): adjust Z for X@Y` — together they form the atomic unit).
- **D-03:** PR title: `chore(03.0.2): dependency refresh — N major bumps`. PR body lists every bump with its rationale (one line each) plus the smoke-CI link as the load-bearing trust signal.

### Commit grouping (family grouping)

### Risk handling
- **D-06:** Complete every bump in this phase. Phase does not close until all 15 majors are on latest stable. If a bump produces non-trivial breakage (e.g., TypeScript 6 strictness regressions across N files, drizzle schema regeneration drift, better-auth OAuth contract change, pino redact-path API drift), the agent fixes the code and lands the fix-up in the same atomic unit. No "defer this one to phase 03.0.3" escape hatch.
- **D-07:** **Special vigilance** on three bumps because they touch invariants that AGENTS.md treats as load-bearing:
  - **pino 10** — the `REDACT_PATHS` contract in `src/lib/server/logger.ts` AND the redact-coverage test in `tests/unit/logger.test.ts` MUST stay green; verify pino 10 has not changed `redact.paths` syntax. Privacy floor (AGENTS.md "Privacy & multi-tenancy" item 6).
  - **dotenv 17** — must NOT break the "only `src/lib/server/config/env.ts` reads `process.env`" invariant (ESLint `no-restricted-properties` enforces). Verify dotenv 17 still exports the same `config()` shape.
  - **better-auth** — touches the OAuth dance. Smoke test (production image + oauth2-mock-server) is the load-bearing assertion. If smoke fails, fix the integration before merging the bump commit.
- **D-08:** Drizzle pair (added 2026-05-11): if the bump regenerates SQL differently for existing migrations, **forward-only migration** rule (AGENTS.md Practices) still holds — no "down" migrations, no rewriting of merged migrations. New drift gets a new migration file, not edits to old ones. `pnpm db:check` must stay no-diff at end of fix-up.

### Scope expansion (2026-05-11)
- **D-09:** Three packages from issue #23's "Out of scope" are pulled IN to this phase: `drizzle-orm`, `drizzle-kit`, `better-auth`. Rationale captured during discuss-phase: user's intent is "обновить все зависимости" — formal "out of scope" status only made sense for packages that can't be bumped (already-on-latest cases). drizzle and better-auth are bumpable; their pre-1.0/recent-prod-deploy risk profile is real but accepted under D-06.
- **D-10:** Truly out of scope (cannot be bumped or no major available):
  - `svelte` — already on latest major 5.x (no 6.x)
  - `hono` — already on latest major 4.x (no 5.x)
  - `pg` — already on latest major 8.x (no 9.x)
- **D-11:** Minor/patch refresh of non-major packages is OUT of scope for this phase. If after the major bumps a `chore(deps): minor+patch refresh` PR is wanted, that is a separate PR outside this phase boundary.

### Established Patterns
- **Conventional Commits**: every commit follows `chore(scope): …` / `fix(scope): …`. Per-bump commits use `chore(deps): bump X from A to B` shape; per-bump fix-ups (when needed inside the same atomic unit) use `fix(03.0.2): <reason>`.
- **`package.json` pin style**: load-bearing packages are pinned without `^` (e.g. `"better-auth": "1.6.9"`, `"drizzle-orm": "0.45.2"`, `"pg-boss": "12.18.2"`, `"pino": "^9.5.0"` — mixed). The phase should normalize the new versions following the existing per-package convention: load-bearing stays exact-pinned, dev/tooling stays caret-ranged. Planner decides per-package per existing pattern.
- **Phase branch model**: `feat/phase-NN-slug` branch already created (`feat/phase-03.0.2-dependency-refresh`); existing convention — no new branch needed.

### Integration Points
- **`package.json`** — every commit touches `dependencies` or `devDependencies`. `pnpm-lock.yaml` updates with each.
