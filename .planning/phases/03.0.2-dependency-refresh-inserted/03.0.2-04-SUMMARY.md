### Source fix-ups for ESLint 10's three new `eslint:recommended` rules

ESLint 10 adds three rules to `eslint:recommended` (per the [v10 migration guide](https://eslint.org/docs/latest/use/migrate-to-10.0.0)):
- `no-unassigned-vars` — `let x;` declared and never assigned
- `no-useless-assignment` — variable assigned and immediately overwritten without read
- `preserve-caught-error` — `catch (e) { throw new Error(...) }` losing the original cause

`pnpm lint` after the bump surfaced 4 violations across 4 files. All fixed at the source:

#### Fix 1: `preserve-caught-error` in `src/lib/server/auth-adapter.ts:101`

The envelope-decrypt path catches a JSON-parse error and rethrows a domain-specific error. The original parse-error reason was being discarded.

```diff
   } catch (err) {
     logger.error({ err }, "envelope: failed to parse stored token JSON");
-    throw new Error("envelope: malformed stored token");
+    throw new Error("envelope: malformed stored token", { cause: err });
   }
```

**Privacy note:** The catch already pino-logs `{ err }` through the redact filter (no secret leakage); attaching `cause: err` to the rethrown Error preserves the parse-error chain for post-incident diagnosis without changing the public error shape callers see.

#### Fix 2: `no-useless-assignment` in `src/lib/sources/youtube/server/handlers/channel-context-backfill.ts:580`

`let authorIsMe = false` was overwritten unconditionally inside the `if (sourceId) { ... }` block (line 591) before any read. The initializer was dead.

```diff
-  let authorIsMe = false;
   if (sourceId) {
     ...
     const sourceRow = await db
       .select({ isOwnedByMe: dataSources.isOwnedByMe })
       .from(dataSources)
       .where(and(eq(dataSources.id, sourceId), eq(dataSources.userId, userId)))
       .limit(1);
-    authorIsMe = sourceRow[0]?.isOwnedByMe ?? false;
+    const authorIsMe = sourceRow[0]?.isOwnedByMe ?? false;
```

**Behavioral identity preserved:** the variable is only ever read inside the same `if (sourceId)` block (inside `.values({ authorIsMe })` on line 656). When `sourceId` is NULL, the entire auto-import block is skipped and the variable is never referenced, so moving the declaration inside the block and tightening to `const` is a no-op at runtime. The surrounding comment block (the auto-import idempotency narrative) is untouched.

#### Fix 3: `no-useless-assignment` in `src/lib/sources/youtube/server/http.ts:201`

In the 403-response classifier, `let reason: string | null = null` was overwritten unconditionally by both the try-block AND the catch-block before any read.

```diff
   if (resp.status === 403) {
-    let reason: string | null = null;
+    let reason: string | null;
     try {
       const body = (await resp.clone().json()) as {
         error?: { errors?: { reason?: string }[] };
       };
       reason = body?.error?.errors?.[0]?.reason ?? null;
     } catch {
       reason = null;
     }
```

**Behavioral identity preserved:** every code path through the try/catch assigns `reason` before it is read on line 210 (`if (reason === "quotaExceeded")`).

#### Fix 4: `no-useless-assignment` in `tests/unit/logger.test.ts:20`

Same pattern — `let logger: unknown = null` was overwritten unconditionally by the try-block before any read; the catch-block early-returns.

```diff
   it("logger module exposes pino-shaped interface", async () => {
-    let logger: unknown = null;
+    let logger: unknown;
     try {
       const mod = await import("../../src/lib/server/logger.js");
       logger = (mod as { logger?: unknown }).logger ?? mod;
```

**Behavioral identity preserved:** the catch-block early-returns before any read of `logger`, so the dropped initializer is reached zero times.
