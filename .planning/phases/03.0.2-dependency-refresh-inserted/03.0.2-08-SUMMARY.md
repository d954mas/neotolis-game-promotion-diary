## Decisions Made

- **Caret pin `^6.0.3` (not `~6.0.0`).** Followed the existing devDeps caret convention. The @typescript-eslint v8 peer range `>=4.8.4 <6.1.0` is the operational upper guardrail; if pnpm ever attempted to resolve to 6.1.x, the install would fail at the peer-dep step and we'd see it immediately on the next `pnpm install --frozen-lockfile`. AGENTS.md "Locked stack versions" practice already mandates that any future major (or breaking minor) goes through its own dedicated PR with rationale, so the caret range does not create silent-bump risk.
- **No fix-up commit.** The atomic unit is one commit. RESEARCH.md §Commit 4 allowed a fix-up if `noUncheckedSideEffectImports` surfaced real errors; the audit + first-run typecheck proved no fix-up was needed.
- **Prettier touch-up applied to modified files before commit.** Standard procedure carried forward from plans 01-07 (the only Prettier delta was the typescript line in package.json). The pre-existing 125-file CRLF Prettier baseline (down from 126 in the prior commit, net -1) remains the non-blocking baseline — ESLint alone (`pnpm exec eslint .`) exits clean.
