Land the eighth atomic commit of Phase 03.0.2: bump `typescript` from ^5.6.3 to ^6.0.x.

Per RESEARCH.md §"Commit 4", TS 6.0 carries the largest set of breaking changes since TS 2.0 — but our `tsconfig.json` is already pre-immunized:
- `strict: true` (TS 6 default flipped to true — we set explicit, no change)
- `types: ["node", "vitest/globals"]` (TS 6 default flipped to `[]` — we set explicit, no change)
- `target: "ES2022"` (TS 6 default `es2023` — we set lower explicit, safe)
- `module: "ESNext"` (TS 6 default `esnext` — we set explicit, no change)
- `esModuleInterop: true` (TS 6 forbids `false` — we set true, safe)

The ONE new strict check that may surface real errors is **`noUncheckedSideEffectImports`** (TS 6 default: false → true). We don't set this; the new default may flag side-effect-only imports like `import "./foo"`. Expected hit rate is low.

Peer-dep compatibility: `@typescript-eslint/eslint-plugin` 8.59.2 peer-dep is `typescript: ">=4.8.4 <6.1.0"` — **TS 6.0.x is in range; 6.1 would break.** Pin to `^6.0.x` (caret-scoped to 6.0.minor.patch) using the explicit constraint `"typescript": "^6.0.0"` — pnpm's caret semantics for `^6.0.0` allow 6.0.x but NOT 6.1.x. Alternative: `~6.0.0` if planner wants tighter control. Either is acceptable; the contract is "don't sneak 6.1 in."

Risk profile: MEDIUM. The plan budgets for a fix-up commit if `noUncheckedSideEffectImports` surfaces real errors. D-06 forbids relaxing tsconfig to mask errors; fix the code instead.

Purpose: Bring TypeScript to its latest major; preserve @typescript-eslint compatibility; uphold strict-type-checking discipline (no relaxation).
Output: One commit `chore(deps): bump typescript from ^5.6.3 to ^6.0.x` (with optional fix-up commit for noUncheckedSideEffectImports hits) on `feat/phase-03.0.2-dependency-refresh`; CI green on all three jobs.
