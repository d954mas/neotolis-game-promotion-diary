## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] pnpm TLS certificate chain rejected by bundled Node CA bundle**

- **Found during:** Task 1, first `pnpm add -D @types/supertest@^7.2.0` attempt.
- **Issue:** pnpm exited with `UNABLE_TO_VERIFY_LEAF_SIGNATURE` on every `registry.npmjs.org` request, including the @types/supertest tarball itself. Error message itself hinted: "if the root CA is installed locally, try running Node.js with --use-system-ca".
- **Fix:** Re-ran with `NODE_OPTIONS="--use-system-ca"` prefix. Resolved on retry; tarball downloaded; package.json + pnpm-lock.yaml updated as expected.
- **Files modified:** none beyond what the plan called for (`package.json`, `pnpm-lock.yaml`).
- **Verification:** `pnpm install --frozen-lockfile` exit 0 confirmed lockfile/manifest sync; `pnpm typecheck` exit 0; `pnpm test:unit` 324/324 green.
- **Committed in:** N/A (no committed change — workaround is invocation-level, applies to the next 9 commits too).

**2. [Rule 3 - Blocking] Windows pnpm wrote CRLF line endings to package.json; `pnpm exec prettier --check package.json` failed**

- **Found during:** Task 1, post-bump verification (`pnpm exec prettier --check package.json pnpm-lock.yaml`).
- **Issue:** Windows `pnpm add` writes the manifest using OS-native CRLF line endings. The project's `.prettierrc` defaults to `endOfLine: lf`, so Prettier rejected the working-copy file — even though Git's `core.autocrlf=true` would normalize the staged blob to LF on commit (so the committed bytes would still be LF and CI on Linux would pass). Local `pnpm lint` reported 128 files mismatched (pre-existing on this Windows checkout — see deviation 3).
- **Fix:** Ran `pnpm exec prettier --write package.json pnpm-lock.yaml` to rewrite the working-copy files with LF endings. Diff stayed exactly one logical change (the version bump); no spurious whitespace edits leaked into the commit.
- **Files modified:** `package.json` (line-ending normalization, no semantic change), `pnpm-lock.yaml` (line-ending normalization, no semantic change).
- **Verification:** `pnpm exec prettier --check package.json pnpm-lock.yaml` after fix prints "All matched files use Prettier code style!"; `git diff --stat HEAD~1 HEAD` shows exactly 2 files / 6 insertions / 6 deletions; CI on Linux runners is green.
- **Committed in:** `4ec4c6a` (same task commit — folded into the atomic unit).

**3. [Out of scope — logged to deferred-items.md, NOT fixed] Pre-existing `pnpm lint` failure on Windows checkout (~128 files)**

- **Found during:** Task 1, pre-commit `pnpm lint` invocation.
- **Issue:** `pnpm lint` reports `Code style issues found in 128 files. Run Prettier with --write to fix.` against files this commit does NOT touch.
- **Root cause:** Same Windows-CRLF/Prettier mismatch as deviation 2, but at working-tree scope. Confirmed pre-existing by `git stash` of the bump + re-running `pnpm lint` on the un-bumped tree: 129 files (vs 128 post-bump), so this failure exists on every Windows checkout of this branch independent of the bump.
- **Out of scope per SCOPE BOUNDARY:** "Pre-existing warnings, linting errors, or failures in unrelated files are out of scope. Log out-of-scope discoveries to deferred-items.md ... Do NOT fix them."
- **Honest CI signal:** Master CI run 25637209245 (HEAD a870ddb, same tree minus the bump) was green; PR #26 CI run 25652272304 (with the bump) is green. Linux CI is the load-bearing assertion per D-02. Local lint on Windows is informational.
- **Deferred to:** Follow-up `chore: normalize line endings to LF on checkout` PR after Phase 03.0.2 ships. See `deferred-items.md` for the proposed fix (`* text=auto eol=lf` in `.gitattributes`).
